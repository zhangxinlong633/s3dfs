# 使用这个压缩包

这是某一系统、某一架构的 s3dfs 程序包。解压后直接运行，不必在目标机器上编译。索引不在这个包里，要另外启动 dleveldb。数据放在 `/var/lib/s3dfs`，换版本时不要删除这个目录。

包内 `VERSION` 是版本号。本机需要 `bun`，systemd 单元使用 `/usr/bin/bun`。

## 取得并解压

从对应标签的 GitHub Release 下载与机器系统、架构一致的文件，例如 `s3dfs-0.1.1-linux-x64.tar.gz`。

```bash
sudo mkdir -p /opt/s3dfs
sudo tar -C /opt/s3dfs -xzf s3dfs-0.1.1-linux-x64.tar.gz
cat /opt/s3dfs/VERSION
```

## 一台机器

索引已经在 `127.0.0.1:9800` 时，启动这一台的 API。它同时打开本机磁盘，并在 :9100 上给其他节点写。正式环境要填写同一对密钥，并保持严格布局开启：

```bash
sudo mkdir -p /var/lib/s3dfs/block/block1
export S3DFS_INDEX_URLS=http://127.0.0.1:9800
export S3DFS_BLOCK_NODES=block1=127.0.0.1:9100
export S3DFS_BLOCK_NODE_ID=block1
export S3DFS_BLOCK_PORT=9100
export S3DFS_BLOCK_ADVERTISE=127.0.0.1:9100
export S3DFS_DATA_DIR=/var/lib/s3dfs/block/block1
export S3DFS_DATA_REPLICAS=1
export S3DFS_STRICT_LAYOUT=0
export S3DFS_ACCESS_KEY=访问密钥
export S3DFS_SECRET_KEY=秘密密钥
cd /opt/s3dfs
bun api/main.js
curl -fsS http://127.0.0.1:9000/_s3dfs/health
```

巡检和控制台也在这个目录里：

```bash
cd /opt/s3dfs
S3DFS_PATROL_API_URL=http://127.0.0.1:9000 S3DFS_PATROL_TOKEN=巡检令牌 bun patrol/main.js
npm run start:web
```

控制台默认监听 `:9001`。

## 多台机器

程序仍然用本压缩包解压到每台机器的 `/opt/s3dfs`。副本数、索引地址和故障域用仓库里的环境文件生成 systemd、Docker Compose 或 Kubernetes 清单，见仓库 [部署](https://github.com/zhangxinlong633/s3dfs/blob/main/docs/deploy.md) 第 8 节。生成出来的单元从 `/opt/s3dfs` 启动，不在目标机器上重新编译。

要做成镜像时，用解压后的目录当构建上下文，不要用 git 源码：

```bash
docker build -f deploy/docker/runtime.Dockerfile -t s3dfs /opt/s3dfs
```

`deploy/docker/runtime.Dockerfile` 在源码仓库里。镜像只复制已经解压的程序。
