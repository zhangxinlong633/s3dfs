## 四档都跑够数秒

16 核本机和打向它的那一路同时开始。8 核打自己的进程等这两路结束之后单独跑。叠在一起时，16 核发出的副本会把 8 核那条线程上的单次写入拖到数秒。

| 写入 | 次数 | 16 核，本机 API | 8 核，打到 16 核的 API | 8 核，本机 API |
| --- | ---: | ---: | ---: | ---: |
| 1 KiB | 40,000 | 3,667 次/秒，10.9 秒 | 2,700 次/秒，14.8 秒 | 626 次/秒，63.9 秒 |
| 10 KiB | 12,000 | 2,106 次/秒，5.7 秒 | 412 次/秒，29.1 秒 | 888 次/秒，13.5 秒 |
| 100 KiB | 4,000 | 515 次/秒，7.8 秒 | 884 次/秒，4.5 秒 | 520 次/秒，7.7 秒 |
| 1 MiB | 600 | 49 次/秒，12.3 秒 | 126 次/秒，4.8 秒 | 33 次/秒，18.4 秒 |

打向 16 核的 10 KiB 整段都叠在本机还在写更大对象的时候。它的 100 KiB 和 1 MiB 是本机那一路结束之后测的。16 核本机这四档都和另一路叠在一起。

API 那条线程上的索引写入仍大约 0.03 毫秒。32 个叠在这一段大约 1 毫秒。1 KiB 在 16 核上持续 10.9 秒仍是 3,667 次/秒。
