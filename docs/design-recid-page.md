# recId 页

| | |
| --- | --- |
| 读者 | 要知道 `recId` 怎么在 `.blk` 里找到偏移的人 |
| 本文回答 | 一页 80 KiB 怎么放下 20480 个槽，内存里留什么，读一次对象多读几次盘 |

数据位置仍只记节点和 `recId`，不记盘上偏移。偏移写在 `.blk` 开头的 TLV 页里。进程不把每一条 `recId` 放进内存，只记住这个文件里每一页的起点。

打开目录时读每一页的 22 字节头和 80 KiB 槽，用来填页表和知道哪些格已经写过。不读对象正文。旧的整文件扫描不再用来找 `recId`。

## 一个文件里的页

每个 `.blk` 开头是一页。页本身是一条 TLV，类型是 `RECID_v1`。后面的值是 20480 个槽，每格 4 字节，一共 80 KiB。格里只放本文件内的偏移。块号就是这一页所在的文件，不另存。记录长度在那个偏移上的对象 TLV 里，格里也不存。偏移用 `u32`，能指到 4 GiB；一个 `.blk` 是 1 GiB，够用。0 表示这一格是空的。

20480 格都是数据。下一页在本文件中的偏移写在页头里；没有下一页时为 0。

这一页写满以后，仍在同一个 `.blk` 后面再放一页，上一页头里的下一页偏移指向它。页不跨文件。文件写到 1 GiB 时，最后一页里没写上的格空着。下一个 `.blk` 自己从新的一页开始，不接这些空格。对象记录和它的槽在同一个文件里。

```
blk 0001                                                        1 GiB
+-----------------------------------------------------------------------+
| type                u16     RECID_v1                                  |
| len                 u32     页头其余字段加 80 KiB 槽                   |
| first recId         u64     本页第 0 格的 recId                        |
| next                u32     下一页在本文件的偏移，没有则为 0           |
| 保留                u32     写入时填 0，打开时不核对                    |
| [0] [1] ... [20479] 每个 u32 是本文件偏移，0 为空           80 KiB    |
+-----------------------------------------------------------------------+
| 对象记录。头是 magic、total、KIND、REC_ID、MTIME、CRC、VALUE          |
| 有分片才带 PREV、SEQ、GENERATION、TOTAL_SIZE、EXTENT_CNT               |
| 有压缩才带 COMPRESS、ORIG_SIZE、ORIG_CRC                               |
+-----------------------------------------------------------------------+
| 页 1。同一套头。first recId 是这一页第 0 格。next 为 0 则没有下一页    |
+-----------------------------------------------------------------------+
| 对象继续追加，直到 1 GiB。最后一页没写满的格空着                        |
+-----------------------------------------------------------------------+

blk 0002
+-----------------------------------------------------------------------+
| 自己的页 0。first recId 从本文件第一条算起                              |
+-----------------------------------------------------------------------+
```

分片和压缩那些 TLV 只出现在对象记录上。`recId` 页没有 key。

## 内存

内存里按文件留下页的起点：文件号、这一页第 0 格的 `recId`、页在文件中的偏移、下一页偏移。一页一条。对象本身不进这张表。

对象平均 10 KiB 时，一页覆盖约 200 MiB 正文，一个 1 GiB 文件大约 5 页，页表大约几百字节。对象平均 1 MiB 时，一个 1 GiB 文件大约一千条记录，页 0 就够，其余格子空着，页表只有一条。

## 读盘

写下一条记录时，对象字节先落到文件，然后只定位写这一格的 4 字节。不再重算这 80 KiB 槽的 CRC，也不改页头里那 4 字节。其余格子留在盘上，不整页重写。新开一页时才把整页写一次。

一块盘默认同时开 8 个 `.blk`，最多 32 个（`S3DFS_WRITE_BLOCKS`）。每个写入线程只打开自己的那一个文件，各写各的页。同一个 key 总是进同一条线程，避免两笔覆盖抢同一条记录。

查到数据位置里的 `recId` 之后，用页表算出页号和格号，再读那一格的 4 字节。块号用这一页所在的文件，长度用偏移处对象 TLV 的 `total`。多出来的是这一次槽位读取。页表已经在内存里，不用从页 0 顺着页头把每一页读一遍。

这一格通常落在文件系统的一个 4 KiB 块里。正在写的那一页会留在页缓存中，随后的写入不再为这一页去盘。10 KiB 的对象在一个文件里大约 5 页；1 MiB 的对象通常只有页 0。两种都是多读几次，不是把 `.blk` 再读一遍。

打开文件时读每一页的头和 80 KiB 槽，用来填页表。不核对页头里那 4 字节。对象正文留在后面。一个 1 GiB、对象约 10 KiB 的文件，这些页合计约 400 KiB。
