# 与 APFS 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 Apple 文件系统里拿克隆、共享空间和元数据校验的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| APFS | 以 Apple 的文件系统参考和安全指南为准。2016 年 Adam H. Leventhal 对校验和的说明与之一致 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 APFS 多出来的部分 |

APFS 是 Apple 平台上的本地文件系统，面向闪存。一个容器里多个卷共享剩余空间。元数据对象带校验和，用户数据块不校验。同卷克隆只改元数据，直到某一边被改写。s3dfs 的 Copy 今天仍是把字节读出来再写入。

## 标准对照

| 项 | s3dfs | APFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | Mac、iPhone 上的系统卷和数据卷。本机拷贝要立刻共享空间 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器上的一个容器 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 容器里的元数据对象。每个对象带 8 字节 Fletcher-64 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 用户数据块。文件系统不给这些块做校验，靠盘上的 ECC |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 卷里的路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 文件系统不跨机器复制。冗余在盘上 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 元数据写时复制。事务结束时写检查点，读者看到检查点之后的卷 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读元数据时核对 Fletcher-64。用户数据对不上时，没有另一份对象副本可换 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 元数据坏了会牵出这一卷。用户数据的静默损坏靠盘 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 从最后一个检查点继续。写了一半的元数据事务不会成为新的卷状态 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 容器里的剩余空间给所有卷共用。不因为加了卷就把旧文件搬走 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 快照按写时复制留住某一刻。macOS 11 起系统卷从快照启动 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 不按对象做 zstd。空间账在容器，不按卷把盘划死 |
| 拷贝 | CopyObject 读出再写入 | 同卷克隆只更新元数据。两边之后的修改才分配新空间 |

## 特色

| 只在 APFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 容器共享剩余空间 | 多个卷只占自己写下的部分，剩下的空间还在容器里。不必先把盘划成互不相通的分区 | 每台 block 自己的 `.blk`。桶没有配额，也不共享一块剩余空间账 |
| 克隆 | 同卷拷贝先共享 extent。调用方改一边，才给那一边分配新块 | CopyObject 把字节读出来再写入。另一台 block 上是独立的一份 |
| 元数据和用户数据的校验分开 | 元数据对象有 Fletcher-64。用户数据块没有文件系统校验 | 记录 CRC 和 locator 上的正文 CRC 都做。不把用户数据的校验让给盘 |
| 按卷加密 | 系统卷和数据卷分开。预启动卷和恢复卷不加密 | 一把 AES256，只覆盖放得进 1 MiB 缓冲的对象 |
| 从快照启动 | 系统卷可以停在某一个快照上，本机改动落在另一层 | 没有「集群从某一个快照启动」 |

## 留下的

同池拷贝可以先共享底层块，调用方改一边再写新块。多个卷共享剩余空间，快照和加密按卷设，不必先把盘划死。元数据校验和用户数据校验是两件事：元数据坏了会牵出一大片，值得单独保护。

## 不照搬的部分

用户数据不靠 APFS 自己做端到端校验，s3dfs 继续在记录和 locator 里记 CRC。克隆和共享空间都在一台机器的容器里，不替换跨 zone 的副本。S3 Copy 仍读出再写入；同池共享块只留作以后的拷贝优化，不在上线八项里。
