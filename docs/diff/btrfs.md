Btrfs 是一台机器上的文件系统。它用写时复制、子卷和 balance 管一块或几块本地盘。s3dfs 的多台 block 不组成一个 Btrfs 卷。单机盘用什么文件系统是部署选择，不进入 S3 的冗余。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | Btrfs |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 几棵写时复制的 B 树装在同一台机器的块设备上。chunk 树把逻辑地址映射到物理盘，checksum 树另存校验，文件树存目录和 extent |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | B 树节点常见 16 KiB。键是对象号、类型和偏移。extent 指向一段逻辑地址。默认扇区跟随页大小。数据和元数据可以分别指定单盘、双盘或 RAID |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 路径在文件树里。extent 给出逻辑地址，chunk 树再把逻辑地址换成某几块盘上的物理位置。校验不放在 extent 指针里，而放在 checksum 树，键是逻辑地址 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 修改写出新的数据块和新的树节点，最后用一次树根替换提交。崩溃后挂载使用上一棵完整的树。没有跨机器的法定人数 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 读 extent，再按逻辑地址到 checksum 树取 crc32c 核对。nodatasum 会关掉数据校验。有第二份物理副本时，scrub 或读失败可以用另一份 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | crc32c 在 checksum 树，不在父指针，也不在数据块尾部。块自己被换成另一段 crc 也正确的数据时，仍然要对逻辑地址。这和 ZFS 把校验放进 blkptr 不是同一种摆法 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | RAID 1/10 是整份镜像。RAID 5/6 是条带加校验，这一档不能当作唯一副本。没有镜像时，crc 对不上就只能报错 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 树节点随文件和 extent 涨，都在本机。子卷是一棵文件树的根。快照是这个根的写时复制引用，不是把每个文件再写一条中心索引 |

## 标准对照

| 项 | s3dfs | Btrfs |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 一台 Linux 上的文件。子卷用来做快照、配额和压缩 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器上的一块或多块盘 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 写时复制的元数据树。元数据里带 crc32c |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 写时复制的数据块。修改写出新块，再更新元数据 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 子卷里的路径。快照是子卷的一个名字 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 盘内 RAID 0/1/10。RAID 5/6 长期不能当作唯一副本 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 事务把新块和元数据一起提交。读者看到的是提交之后的树 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 数据和元数据默认都有 crc32c。校验值在单独的 checksum 树里，按逻辑地址索引，不写在父指针里。`nodatasum` 可以关掉数据校验 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 镜像盘可以替换。RAID 5/6 不能拿来当这份数据的唯一副本 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 写时复制。崩溃后从最后一次提交的树根继续 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加盘之后用 balance 把已有数据在新旧盘之间搬匀 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 子卷快照。send/receive 复制快照差 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 子卷上可以开 zstd。配额挂在子卷上 |
| 拷贝 | CopyObject 读出再写入 | 快照和 send/receive 共享或复制块。没有 S3 Copy |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | Btrfs |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 规则自动。RAID 1/10 上的 scrub 可以用另一份副本修元数据和数据。RAID 5/6 不能当作这份数据的修复手段 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 在 API 进程内存里，重启从 0 再计 | 手工。scrub 和 balance 要人安排。加盘不会自己把旧数据搬匀 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。没有用模型读子卷或校验结果 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。没有把所有 `.blk` 再读一遍的 scrub | 规则自动。scrub 把数据读出来，和 checksum 树里的 crc32c 对。有镜像时可以用另一份修。校验不在父指针里，发现方式和 ZFS 不同 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。没有接上外部值班系统，也没有自动升级 | 手工。内核日志里有错误。没有独立的值班升级流程 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。没有把所有 `.blk` 再读一遍并修好的闭环，告警也没有接上外部值班 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 修完会留下计数，scrub 覆盖没人读过的块。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、IAM、KMS、Object Lock 和站点复制不在这张差距表里。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把所有 `.blk` 再读一遍，能修的当时修，修完留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警没有接上外部值班，升级没有交给值班的步骤。本机 localhost 的通过不能当作唯一副本 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | Btrfs |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 子卷快照不用先拷贝整盘。send/receive 只送快照之间的差。RAID 1/10 读到坏副本时可以改用另一份 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | balance 会搬已有数据，读写放大要人盯。RAID 5/6 不能当唯一副本，这个界限要人守，文件系统不会替人改掉这个选择。scrub 不是装好就天天跑 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 写时复制把新块和元数据一起提交。崩溃后回到上一棵一致的树。这不防止删除子卷 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 默认把读出的数据和 checksum 树里的 crc32c 对。没有第二份物理副本时，对不上就报错，不能改读另一份 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 快照还在，就可以从快照里把文件拷回来。快照删了，这次删除就没有系统内的退路 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 重启后从 0 再计，盘上的丢失还在 | 冗余只在这台机器的几块盘之间。机器没了，子卷和快照一起没 |
| 另一场地 | 没有把对象自动送到另一套集群、另一机房或一块备份盘。3 副本是这一套集群里的三台 block | send/receive 的目标和保留要人安排。不送出去，就没有另一台机器上的副本 |

## 特色

| 只在 Btrfs 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 子卷 | 快照、配额、压缩的边界是子卷，不是整块盘 | 桶是 key 前缀。没有配额，压缩是全局默认 |
| balance | 加盘之后主动把已有 extent 搬到新盘。搬的时候有读写放大，要单独做 | 加 block 之后旧 locator 留在原节点。新写入才落到新机器 |
| RAID 5/6 的界限 | 这两种级别长期不能当作唯一副本。能用的是 RAID 0/1/10 | 对象的唯一副本是 3 份整对象，不在单机上做 RAID 5/6 |
| send / receive | 把子卷快照的差送到另一台。差是块，不是按路径把每个文件再读一遍 | 没有子卷流。版本是 `$ver/` 里的对象正文 |

## 留下的

子卷说明配额和快照需要一个比「整个盘」更小的边界。balance 说明加盘之后搬旧数据是一次单独的任务，要算读写放大，不能假装新盘一加上旧数据就均匀了。

## 不照搬的部分

s3dfs 加 block 之后仍不搬旧 locator，这和 balance 的选择相反，维持这个选择。RAID 5/6 不拿来当对象的唯一副本。send/receive 留作整机备份的参照，不做成在线 S3 复制。
