Btrfs 是一台机器上的文件系统。它用写时复制、子卷和 balance 管一块或几块本地盘。s3dfs 的多台 block 不组成一个 Btrfs 卷。单机盘用什么文件系统是部署选择，不进入 S3 的冗余。

## 标准对照

| 项 | s3dfs | Btrfs |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 一台 Linux 上的文件。子卷用来做快照、配额和压缩 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器上的一块或多块盘 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 写时复制的元数据树。元数据里带 crc32c |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 写时复制的数据块。修改写出新块，再更新元数据 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 子卷里的路径。快照是子卷的一个名字 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 盘内 RAID 0/1/10。RAID 5/6 长期不能当作唯一副本 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 事务把新块和元数据一起提交。读者看到的是提交之后的树 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读元数据时核对 crc32c。数据块的校验没有 ZFS 那种放在父指针里的端到端校验 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 镜像盘可以替换。RAID 5/6 不能拿来当这份数据的唯一副本 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 写时复制。崩溃后从最后一次提交的树根继续 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加盘之后用 balance 把已有数据在新旧盘之间搬匀 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 子卷快照。send/receive 复制快照差 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 子卷上可以开 zstd。配额挂在子卷上 |
| 拷贝 | CopyObject 读出再写入 | 快照和 send/receive 共享或复制块。没有 S3 Copy |

## 特色

| 只在 Btrfs 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 子卷 | 快照、配额、压缩的边界是子卷，不是整块盘 | 桶是 key 前缀。没有配额，压缩是全局默认 |
| balance | 加盘之后主动把已有 extent 搬到新盘。搬的时候有读写放大，要单独做 | 加 block 之后旧 locator 留在原节点。新写入才落到新机器 |
| RAID 5/6 的界限 | 这两种级别长期不能当作唯一副本。能用的是 RAID 0/1/10 | 对象的唯一副本是 3 份整对象，不在单机上做 RAID 5/6 |
| send / receive | 把子卷快照的差送到另一台。差是块，不是按路径把每个文件再读一遍 | 没有子卷流。版本是 `$ver/` 里的对象正文 |

## 留下的

子卷说明配额和快照需要一个比「整个盘」更小的边界。balance 说明加盘之后搬旧数据是一次单独的任务，要算读写放大，不能假装新盘一加上旧数据就均匀了。

## 不照搬的部分

s3dfs 加 block 之后仍不搬旧 locator，这和 balance 的选择相反，维持这个选择。RAID 5/6 不拿来当对象的唯一副本。send/receive 留作整机备份的参照，不做成在线 S3 复制。
