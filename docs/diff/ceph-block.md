# 与 Ceph Block 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要把虚拟机或容器的磁盘做成多副本，同时又在看对象存储的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| Ceph Block | 以 Ceph 文档里的 RBD、librbd 和 RADOS 池为准。CephFS 见 [cephfs.md](cephfs.md)。RGW 见 [mainstream.md](mainstream.md) |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 RBD 多出来的部分 |

RBD 把一块盘交给一个写入者。镜像切成 RADOS 对象，条带落在 OSD 上。调用方看见的是块设备，不是 bucket 和 key。s3dfs 的一次 Put 是一个对象，不提供「把这 512 字节写到偏移 1 GiB」这种接口。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | Ceph Block |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | librbd 或内核 rbd 把偏移翻译成 RADOS 对象。MON 和 OSD 与 CephFS 共用一套 RADOS。没有 MDS，因为没有目录 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 镜像头对象记下大小、对象大小、条带和特性位。数据对象默认 4 MiB，名字是 rbd_data. 加镜像标识和对象序号。条带可以把连续的扇区散到连续的对象号上 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 偏移除以对象大小得到对象序号，再加上条带参数得到对象名。CRUSH 决定这个对象的 PG 和 OSD。exclusive-lock 保证同一时刻只有一个写入者持有这张镜像 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 一次写变成一个或几个 RADOS 写。复制池达到 min_size 即成功。对象映射（object-map）用位图记下哪些对象真的分配过，快照差异就不必读完整张盘 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 按偏移算出对象名再读。deep-scrub 覆盖这些对象。客户机文件系统自己写进去的错误字节，RBD 当成合法数据，不会用校验和换成应用想写的那一版 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 校验在 OSD 的对象上。object-map 不是校验和，它只说这个对象有没有被写过。快照是一组仍被引用的对象，克隆在改写时才复制那个对象 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 和数据池的设置相同：要么完整副本，要么纠删片。镜像层不再做一次 3 副本。锁是写入者个数，不是副本个数 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 头对象和对象映射是每张镜像一小份。数据对象数约等于镜像大小除以 4 MiB。元数据不随客户机里的文件数涨，因为客户机的文件系统不在 RADOS 里 |

## 标准对照

| 项 | s3dfs | Ceph Block |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 虚拟机、数据库和容器要用的一块盘 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 客户端用 librbd 或内核 rbd。数据在 OSD 上，MON 提供集群图 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 镜像的头部对象记下大小、条带、特性。没有「每个 S3 key 一条 locator」 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 镜像按对象大小切成 RADOS 对象，常见 4 MiB 一个对象，再条带到一组对象上 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 池里的镜像名。快照和克隆挂在这张镜像上 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 池的副本数或纠删配置。常见复制池是 3 份、`min_size` 为 2 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 一个 RADOS 写等到 `min_size` 份副本，或纠删所要求的片。块设备不另写一条对象索引 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读对应偏移上的 RADOS 对象。校验在 OSD，不在一块「对象 CRC」里 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | PG 副本不够时 backfill。镜像没有「这个 key 丢了」的单独计数 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | RADOS 把对象收到一致。客户端用 exclusive-lock 避免两台机器同时写同一张镜像 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加 OSD 后 CRUSH 重算，已有对象会 backfill 到新盘 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 镜像快照。克隆从快照长出来，没改过的块仍和父镜像共享 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes`，超过就拒绝这个桶的 Put | 压缩在池上。配额按池或按镜像的配置，不是 S3 桶 |
| 拷贝 | CopyObject 读出再写入 | 克隆共享父快照的对象。独立拷贝才把块再写一遍 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | Ceph Block |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 闭环。和 RADOS 一样，PG 副本不够就 backfill。镜像没有单独的「这个扇区丢失」计数，结果看在池的健康上 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 写在 `$lost/`，重启后还在。未关闭的故障事件仍在进程内存里 | 产品。镜像的创建和特性由人配，盘和 OSD 的拉起走 Ceph 的编排。块设备挂到哪台机器仍要人定 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。没有用模型读镜像或 PG 的状态 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。`scrub` 按 locator 重写坏副本并把检查数留在索引里，不把没有索引的 `.blk` 再读一遍 | 闭环。deep-scrub 覆盖这块镜像所在的对象。exclusive-lock 不负责发现静默损坏 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 产品。池的健康和慢操作有现成导出。RBD 镜像的跨集群复制要单独配置，不是默认升级 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。scrub 按 locator 留下计数，但没有把没有索引的 `.blk` 再读一遍。告警要配置地址才送出 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 的 scrub 覆盖没人读过的块。s3dfs 的 `scrub` 按 locator 修并留下计数，不扫没有索引的字节。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、KMS 和整集群的站点同步不在这张差距表里。身份账本、对象锁和桶复制开关已经有第一版。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把没有索引的 `.blk` 再读一遍。按 locator 的巡检已经会修并留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有在目标集群测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警只在配置了地址时送出，升级顺序已经写给值班，目标集群还没按这个顺序走过。本机 localhost 的通过不能当作唯一副本 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | Ceph Block |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 放置组会自己补副本，虚机里的盘不用因为一块 OSD 掉线就重新分区。从快照克隆测试盘不用先拷贝整张镜像 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 同一张镜像不要挂给两台虚机写，exclusive-lock 挡住的是第二份写，人仍要避免把同一块盘交给两个写入者。object-map 坏了，快照差会变慢，要人决定是否重建。镜像复制到另一集群要单独配 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 写到池的 `min_size` 或纠删要求即成功。镜像上没有另一层「三个 zone 的对象索引」 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | deep-scrub 覆盖这张镜像的对象。客户机文件系统自己写坏的字节，RBD 会当成合法数据保存，不会用校验和把它换掉 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 删除镜像是人执行的命令，没有回收站。快照还在就可以再克隆一份。快照和镜像都删了，对象就回收了 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 写在 `$lost/`，重启后还在 | 和 CephFS 一样，取决于 CRUSH 有没有把副本分开。池达不到 `min_size` 时，上面所有镜像一起停写，不是只有一块盘停 |
| 另一场地 | 默认不把对象送到另一套集群。桶上打开复制并配置了地址之后，之后的 Put 和 Delete 才送出。3 副本仍是这一套集群里的三台 block | rbd-mirror 把镜像送到另一个集群。不配镜像复制，就没有另一场地 |

## 特色

| 只在 RBD 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 块地址 | 调用方按偏移和长度读写。一个对象内部的布局对调用方不可见 | 调用方按 key 读写整段或一个 Range。没有「这一块盘的第 N 扇区」 |
| exclusive-lock | 同一张镜像同时只允许一个写入者持有锁。第二台要写就得先拿到锁 | 同一个 key 的并发 Put 由后写的 locator 覆盖。没有块设备锁 |
| object-map 和 fast-diff | 用位图记下哪些对象真的被写过。快照差和克隆展开时不必把整张盘读一遍 | 没有「这块盘哪些地方写过」的位图。对象要么整段在，要么不在 |
| 从快照克隆 | 新镜像先共享父快照的 RADOS 对象，写入时才复制被改的对象 | Copy 读出再写入。版本正文在 `$ver/`，不和当前对象共享底层块 |
| 镜像复制 | 快照或日志把一张镜像同步到另一个集群，给虚机做异地副本 | 没有把整块盘同步到另一套集群。对象副本在本集群的 block 上 |

## 留下的

`min_size` 说明写成功可以是「多数副本已经落盘」，不必等齐 3 份。快照克隆说明拷贝可以先共享未修改的块。哪些块被写过可以单独记一张位图，差量备份不必扫完整张盘。

## 不照搬的部分

s3dfs 不做块设备，也不把 key 换成偏移。exclusive-lock 那种单写入者不放进 S3。纠删池和 CRUSH 搬迁不替换 3 副本和「旧 locator 留在原节点」。克隆留作以后的拷贝优化，不在上线八项里。
