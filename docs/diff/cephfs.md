CephFS 给多台机器一个 POSIX 目录树。元数据在 MDS，文件正文是 RADOS 对象，客户端拿到能力之后直接读写 OSD。s3dfs 给调用方指定的 S3 key，不提供目录、硬链接和字节范围里的 POSIX 锁。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | CephFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | MON 维持集群图。OSD 上是 RADOS 对象，按归置组（PG）分布。MDS 只管目录、inode 和能力，并把元数据日志写进元数据池。客户端拿到能力后直接对 OSD 读写 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 文件按布局切成 RADOS 对象，对象大小常见 4 MiB，还可以设条带单元和条带数。MDS 的目录分片是 dirfrag。数据池和元数据池的副本策略分开配 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 路径在 MDS 上解析成 inode。inode 的布局加上偏移，算出对象名。对象名再经 CRUSH 和 PG 落到一组 OSD。客户端缓存的是能力，不是一份永久的 locator 文件 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 数据写进数据池：复制池要达到 min_size，常见配置是 3 份里 2 份；纠删池要凑齐数据片和校验片。MDS 把目录事务写进日志并提交之后，别的客户端才能看见新的目录 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 有能力就按对象名直接读 OSD。没有能力就先问 MDS。RADOS 可以在副本之间换一份。目录的短期旧视图来自能力缓存，不是来自盘上有两份不同的文件 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 对象校验在 OSD。deep-scrub 把对象再读一遍并比较副本。校验不在文件名里，也不在 CephFS 的路径里。元数据池应该用副本，不要用纠删来省那一点容量 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 复制池里一个对象是完整的多份。纠删池里一个对象是 K 个数据片加 M 个校验片。PG 的 acting set 由 CRUSH 算出来，规则决定它们落不落在不同主机 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | MDS 的内存按目录和工作集涨，可以用多个 active MDS 把子树拆开。对象个数随文件字节除以对象大小涨，再加目录本身。小文件仍然是一个个 RADOS 对象 |

## 标准对照

| 项 | s3dfs | CephFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 多客户端同时挂载的 POSIX 文件系统 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | MON 管集群图，OSD 存 RADOS 对象，MDS 管目录。客户端是内核或 ceph-fuse |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | inode、目录和能力在 MDS。MDS 把元数据也写成 RADOS 对象。多个 active MDS 可以按目录分子树 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 文件切成 RADOS 对象，放在数据池。对象大小由布局决定 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 目录路径。可以有硬链接。名字不编码 OSD 位置 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 由池决定。元数据池通常是副本。数据池可以是副本，也可以是纠删 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 客户端按 RADOS 池的 `min_size` 等到足够副本或纠删片。MDS 把元数据事务提交之后，目录才对别的客户端可见 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读 RADOS 对象。副本池可以换一份。OSD 有自己的校验，CephFS 不在文件名上再记一份正文 CRC |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | OSD 掉线后，副本数低于池的要求就恢复（backfill）。MDS 故障由 standby MDS 接管 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | RADOS 的 PG 日志把对象收到一致。MDS 从元数据池里的日志把目录收回一致 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加 OSD 之后 CRUSH 会把已有对象算进新盘，靠 backfill 搬走 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 目录快照。快照里的文件仍指向当时的 RADOS 对象 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 池可以开压缩。目录上可以设配额 |
| 拷贝 | CopyObject 读出再写入 | 文件拷贝是读出再写入。快照本身不把每个文件再写一遍 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | CephFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 闭环。OSD 掉线后，副本数不够的 PG 会 recovery 和 backfill。MDS 由 standby 接管。健康状态里能再看到是否恢复 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 在 API 进程内存里，重启从 0 再计 | 产品。cephadm 和编排器负责部署、换盘和进程拉起。`HEALTH_ERR` 仍要人判断要不要干预 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。健康详情、slow request 和 scrub 是规则报告，不是模型结论 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。没有把所有 `.blk` 再读一遍的 scrub | 闭环。浅 scrub 对元数据，deep-scrub 再读对象数据并核对校验和，能修的副本会修 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。没有接上外部值班系统，也没有自动升级 | 产品。Prometheus 模块和健康摘要给值班。版本升级有文档化的步骤，不是自动跳版本 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。没有把所有 `.blk` 再读一遍并修好的闭环，告警也没有接上外部值班 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 修完会留下计数，scrub 覆盖没人读过的块。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、IAM、KMS、Object Lock 和站点复制不在这张差距表里。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把所有 `.blk` 再读一遍，能修的当时修，修完留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警没有接上外部值班，升级没有交给值班的步骤。本机 localhost 的通过不能当作唯一副本 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | CephFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | OSD 掉线后，副本不够的放置组会自己 backfill，客户端不用改挂载点。MDS 有 standby 可以接管。deep-scrub 按池跑，不用人逐个文件抽查 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | `HEALTH_ERR` 要人分辨是缺副本、盘慢还是满了。纠删池修复时的读放大要人留出带宽。热点目录要人拆到别的 MDS。快照和配额的策略要人定 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 数据按池的 `min_size` 或纠删要求落下才成功。元数据池应使用副本。把目录放进纠删池，修复和读的代价都变大 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | RADOS 的校验加上 deep-scrub，没人读的对象也会被查。客户端的能力缓存可能短时间看见旧目录，这是缓存一致性，不是盘上的副本坏了 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 目录快照还在，可以把文件从快照里拷回。没有快照的删除会回收对象。没有跨集群的回收站 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 重启后从 0 再计，盘上的丢失还在 | CRUSH 把副本放在不同的主机或机柜，才扛得住整机丢失。规则写成同一台机器上的三份时，这台没了就没有源可以 backfill |
| 另一场地 | 没有把对象自动送到另一套集群、另一机房或一块备份盘。3 副本是这一套集群里的三台 block | CephFS 默认不把目录复制到另一套集群。另一机房要人做快照复制或另行镜像。RGW 的多站点是另一条产品，不会自动保护这些文件 |

## 特色

| 只在 CephFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 能力 | 客户端向 MDS 要一段目录或文件的缓存能力。别的客户端要写时，MDS 把能力收回 | 没有客户端缓存的目录能力。每次 Get 问索引 |
| 元数据和数据分开走 | 路径解析走 MDS。字节直接和 OSD 来往，MDS 不转发文件正文 | 取 locator 走索引。字节走 API 和 block |
| 子树分给多个 MDS | 热点目录可以放到另一台 active MDS 上 | 索引按 dleveldb 的环分 key，不按目录子树切 |
| 目录快照和配额 | 快照和配额的边界是目录 | 版本是对象的 `$ver/`。没有目录配额 |
| 同一套 RADOS 上另有 RGW | 对象接口是 RGW，不是 CephFS。两边不要合成一个访问方式 | S3 就是这套 API。没有并行的 POSIX 导出 |

## 留下的

元数据服务确认路径之后，正文不必再经它转发。副本不够时由集群把缺的那一份补上，而不是等下一次写入。目录是配额和快照的边界，比「整个集群一个开关」更细。

## 不照搬的部分

s3dfs 不提供 POSIX：没有目录项、硬链接、字节锁和「打开文件」这种状态。数据池的纠删不替换 `.blk` 的 3 副本。加机器之后不按 CRUSH 把旧 locator 搬走。CephFS 的客户端能力缓存不放进 S3 的 Get。
