FFS 是 BSD 上的本地文件系统。软更新记下元数据之间的依赖，崩溃之后按依赖收拾，不必为每一步元数据都等待一次日志提交。UFS2 有快照。FreeBSD 的 GEOM 在文件系统下面叠镜像、条带、日志和加密，文件系统只看见上面的那一层盘。

## 标准对照

| 项 | s3dfs | FFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 一台 BSD 机器上的系统盘和数据盘 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器。GEOM 可以在这台机器里叠多层盘 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | inode、目录和位图。软更新记下它们之间的依赖顺序 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 文件块在 UFS 的数据区。快照留在 UFS2 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 目录路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 文件系统自己不跨机器复制。镜像在 GEOM，一块盘坏了，机器还在 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 数据要立即可见时同步写。元数据按依赖延后，崩溃后仍能收成一致的目录 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 传统 FFS 不给每个数据块做端到端校验。校验和镜像在 GEOM 那一层才有 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | GEOM mirror 用剩下的盘继续。没有跨机器的对象修复 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 软更新按依赖把元数据恢复到一致。不必启动时把所有文件再读一遍 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加盘是 GEOM 或新文件系统的事。已有文件不因为加了一块盘就搬走 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | UFS2 快照留住某一刻的文件树 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | FFS 本身不做对象压缩。配额是 BSD 的用户配额，不是桶配额 |
| 拷贝 | CopyObject 读出再写入 | 普通文件拷贝。快照是文件系统的某一刻，不是对象 Copy |

## 特色

| 只在 FFS / GEOM 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 软更新 | 记下「目录项必须在 inode 初始化之后」这类依赖。崩溃后按依赖收拾，许多元数据不必每步都等一次日志提交 | 索引按法定人数写入。dleveldb 不实现软更新 |
| 需要立即可见的仍然同步 | 软更新延后的是元数据依赖，不是「数据可以晚一点再落盘还对调用方报成功」 | block 的 flush 默认 `fsync`。2 份成功之后才写索引 |
| GEOM 叠层 | 镜像、条带、日志、加密放在文件系统下面。FFS 只看见上面那一层盘 | API、索引、block 是三种进程。压缩和副本在控制面和引擎里，不在盘驱动里 |
| UFS2 快照 | 某一刻的文件树留在本机，供备份读取 | 版本是 `$ver/` 里的对象，不是本机文件树快照 |

## 留下的

镜像、校验和加密可以放在对象接口下面，调用方只看见上面的一层。这和现在 API、索引、block 分开是同一类分法。崩溃恢复按依赖或按日志把元数据收回一致，不必启动时把所有对象再读一遍。

## 不照搬的部分

软更新不放进 dleveldb。GEOM 的镜像留在单机盘上，不代替跨 zone 的 3 副本。UFS2 快照不做成 S3 版本。
