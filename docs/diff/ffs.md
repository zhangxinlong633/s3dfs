FFS 是 BSD 上的本地文件系统。软更新记下元数据之间的依赖，崩溃之后按依赖收拾，不必为每一步元数据都等待一次日志提交。UFS2 有快照。FreeBSD 的 GEOM 在文件系统下面叠镜像、条带、日志和加密，文件系统只看见上面的那一层盘。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | FFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | FFS 管的是一块逻辑盘上的柱面组和 inode。镜像、加密和日志可以叠在 GEOM 下面，文件系统看不见那一层。没有跨机器的元数据服务 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 经典配置是 8 KiB 块、1 KiB 片，也可以配更大。inode 里是直接块和间接块指针。文件字节在这些块里。UFS2 把快照和扩展属性加在同一布局上 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 目录项指向 inode 号。inode 里的块指针就是物理块号。没有独立的稳定记录号可以让整理碎片不改索引 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 数据要立即可见时同步写。软更新记下元数据依赖，例如目录项不能先于 inode 初始化出现在盘上，崩溃后按依赖收拾，不必每步元数据都等一次日志提交。GEOM 镜像要等它自己的副本策略 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 按 inode 的块指针读。FFS 不对每个数据块做端到端校验。读到的字节是否来自镜像的另一块盘，取决于下面有没有 GEOM mirror |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 没有父指针校验，也没有每块 CRC。一致性靠软更新的依赖顺序，或靠 fsck。GEOM 若另做校验，那是盘变换层，不是 inode 里的字段 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 文件系统这一层只有一份块指针。第二份来自 GEOM mirror，在另一块本地盘上，块号对文件系统不可见 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | inode 和目录随文件数涨，都在这块盘的柱面组里。没有按集群块数估算的中心内存账 |

## 标准对照

| 项 | s3dfs | FFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 一台 BSD 机器上的系统盘和数据盘 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器。GEOM 可以在这台机器里叠多层盘 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | inode、目录和位图。软更新记下它们之间的依赖顺序 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 文件块在 UFS 的数据区。快照留在 UFS2 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 目录路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 文件系统自己不跨机器复制。镜像在 GEOM，一块盘坏了，机器还在 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 数据要立即可见时同步写。元数据按依赖延后，崩溃后仍能收成一致的目录 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 传统 FFS 不给每个数据块做端到端校验。校验和镜像在 GEOM 那一层才有 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | GEOM mirror 用剩下的盘继续。没有跨机器的对象修复 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 软更新按依赖把元数据恢复到一致。不必启动时把所有文件再读一遍 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加盘是 GEOM 或新文件系统的事。已有文件不因为加了一块盘就搬走 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | UFS2 快照留住某一刻的文件树 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | FFS 本身不做对象压缩。配额是 BSD 的用户配额，不是桶配额 |
| 拷贝 | CopyObject 读出再写入 | 普通文件拷贝。快照是文件系统的某一刻，不是对象 Copy |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | FFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 手工。崩溃后用 fsck 按软更新的依赖把目录收一致。GEOM 镜像可以在另一块盘还在时继续读，不自动跨机器补一份 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 在 API 进程内存里，重启从 0 再计 | 手工。快照、fsck 和换盘由人发起。没有周期修复进程 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。没有用模型读文件系统一致性 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。没有把所有 `.blk` 再读一遍的 scrub | 没有。FFS 不给每个数据块做端到端校验。GEOM 若另做校验，那是盘这一层，不是文件系统的巡检 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。没有接上外部值班系统，也没有自动升级 | 手工。系统日志由人看。升级是系统的升级，不是存储产品的升级 |

## 省心与数据保护

这一节写值班的人和数据本身。上一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | FFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 软更新让崩溃后的目录按依赖收回一致，不必为了每一步元数据都先做一次日志提交。GEOM 镜像坏了一块盘，上面的文件系统不用改挂载配置 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | fsck 仍可能要人跑。镜像、加密和日志各在 GEOM 的哪一层，要在装机时叠对。快照是 UFS2 的功能，要人建。没有跨机器的副本 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 同步写的数据在崩溃后还在。软更新保证的是元数据依赖，不是每一份应用数据已经在两块盘上 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 文件系统不给数据块做端到端校验。坏盘要靠 GEOM 镜像或磁盘自己。读到的错字节如果镜像里也没有另一份，就会交给应用 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 没有回收站。UFS2 快照还留着那一刻的文件树时，可以从快照里拷。没有快照的删除就是删除 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 重启后从 0 再计，盘上的丢失还在 | GEOM 镜像救的是这块盘，不是这台机器。机器没了，镜像的两块盘一起不在 |
| 另一场地 | 没有把对象自动送到另一套集群、另一机房或一块备份盘。3 副本是这一套集群里的三台 block | dump 或其他拷贝要人做。文件系统没有把树送到另一台机器的步骤 |

## 特色

| 只在 FFS / GEOM 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 软更新 | 记下「目录项必须在 inode 初始化之后」这类依赖。崩溃后按依赖收拾，许多元数据不必每步都等一次日志提交 | 索引按法定人数写入。dleveldb 不实现软更新 |
| 需要立即可见的仍然同步 | 软更新延后的是元数据依赖，不是「数据可以晚一点再落盘还对调用方报成功」 | block 的 flush 默认 `fsync`。2 份成功之后才写索引 |
| GEOM 叠层 | 镜像、条带、日志、加密放在文件系统下面。FFS 只看见上面那一层盘 | API、索引、block 是三种进程。压缩和副本在控制面和引擎里，不在盘驱动里 |
| UFS2 快照 | 某一刻的文件树留在本机，供备份读取 | 版本是 `$ver/` 里的对象，不是本机文件树快照 |

## 留下的

镜像、校验和加密可以放在对象接口下面，调用方只看见上面的一层。这和现在 API、索引、block 分开是同一类分法。崩溃恢复按依赖或按日志把元数据收回一致，不必启动时把所有对象再读一遍。

## 不照搬的部分

软更新不放进 dleveldb。GEOM 的镜像留在单机盘上，不代替跨 zone 的 3 副本。UFS2 快照不做成 S3 版本。
