# 与 HAMMER2 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 DragonFly 的 HAMMER2 里看卷一级复制和快照的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| HAMMER2 | 以 DragonFly BSD 的 HAMMER2 为准。它是 Matthew Dillon 做的本地文件系统，带卷上的主从复制 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 HAMMER2 多出来的部分 |

HAMMER2 在一台或少数几台机器的卷上做写时复制、快照、CRC、压缩，以及卷一级的主从复制。s3dfs 按对象复制，索引按 key 放在 dleveldb。FFS 和 GEOM 在 [ffs.md](ffs.md)。

## 标准对照

| 项 | s3dfs | HAMMER2 |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | DragonFly 上的本地文件。整卷可以复制到另一台 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台或少数几台机器上的卷 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 卷上的写时复制元数据。修改不覆盖仍被快照参照的块 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 卷上的块。CRC 在卷这一层 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 卷里的路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 卷一级主从。复制的是卷，不是一个 key 的 3 份 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 本卷事务提交。从卷随后跟上，不是写入时的法定人数 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读卷时用 CRC。没有跨 zone 的对象副本可以换 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 从卷可以拿来恢复这一卷。不是按对象把缺少的一份补到第三台 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 写时复制。崩溃后从最后一致的卷状态继续 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 加的是卷或从卷。已有文件留在原卷里 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 快照留住某一刻的卷 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 卷上可以压缩。配额不是 S3 桶配额 |
| 拷贝 | CopyObject 读出再写入 | 卷内可以做重复数据删除。拷贝可以共享块 |

## 特色

| 只在 HAMMER2 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 卷一级主从 | 复制的单位是卷。从卷跟上主卷，不必按 key 把索引扫一遍再逐个 Get | 每个对象写到多台 block。索引里是一条条 locator |
| 快照留在卷上 | 某一刻的块还被快照引用，新写入落到新块 | 版本正文在 `$ver/`。没有整卷快照 |
| 卷内去重 | 相同的块可以只留一份，直到某一边被改写 | 没有去重。Copy 是读出再写入 |
| 卷上的 CRC 和压缩 | 校验和压缩是卷的属性，不是每个对象的 locator 字段 | CRC 在记录和 locator 上。压缩是写入时的默认 zstd |

## 留下的

整卷复制可以一次把数据目录带走，不必按 key 把索引扫一遍。快照让某一刻的卷还在，新写入落到新块。

## 不照搬的部分

主从卷不代替 3 台 block。去重和卷快照不进 S3 的默认路径。对象的唯一副本仍然按 locator 放在多台机器上。
