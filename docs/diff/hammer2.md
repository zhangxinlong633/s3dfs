# 与 HAMMER2 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 DragonFly 的 HAMMER2 里看卷一级复制和快照的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| HAMMER2 | 以 DragonFly BSD 的 HAMMER2 为准。它是 Matthew Dillon 做的本地文件系统，带卷上的主从复制 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 HAMMER2 多出来的部分 |

HAMMER2 在一台或少数几台机器的卷上做写时复制、快照、CRC、压缩，以及卷一级的主从复制。s3dfs 按对象复制，索引按 key 放在 dleveldb。FFS 和 GEOM 在 [ffs.md](ffs.md)。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | HAMMER2 |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存数据位置，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 卷上是一棵写时复制的基树。目录和文件由块引用（blockref）指到下一层。PFS 是卷里的一棵树，可以标成主或从。从卷复制的是树，不是一个 key |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 物理块常见 64 KiB。blockref 里带块的类型、方法和校验码。修改分配新块，再替换父引用。仍被快照引用的块不覆盖 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 路径沿着 blockref 走。引用里既有位置，也有校验方法。没有单独的集群索引把调用方的 key 映射到卷 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的数据位置。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 本卷事务把新块写完再提交根。从卷随后跟上主卷的更新，不是写入当时向三台机器要法定人数。压缩可以在块这一层做 |
| 一次读 | 先取数据位置，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。数据位置里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 按 blockref 读出块，用引用里的校验码核对。方法可以是 CRC，也可以换成更强的校验。没有另一份从卷时，对不上就没有可替换的副本 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和数据位置里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 校验码在 blockref 里，和 ZFS 把校验放在指针里是同一类。它发现的是这一卷上的坏块，不发现另一台机器上的副本哪一份更新 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的数据位置覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 主从是两棵卷树，不是同一段字节的三份对等记录。从卷可以落后。去重若打开，相同的块可以在这一卷里只留一份 |
| 规模 | 每个可见对象至少一条数据位置，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 块引用随树涨，都在卷内。复制到另一台是整棵 PFS，不按文件在中心索引里加一行 |

## 标准对照

| 项 | s3dfs | HAMMER2 |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | DragonFly 上的本地文件。整卷可以复制到另一台 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台或少数几台机器上的卷 |
| 元数据 | 每个对象一条数据位置 JSON（v:3），在 dleveldb。Get 先问索引 | 卷上的写时复制元数据。修改不覆盖仍被快照参照的块 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。数据位置记节点和 `recId`，不记偏移 | 卷上的块。CRC 在卷这一层 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 卷里的路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 卷一级主从。复制的是卷，不是一个 key 的 3 份 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条数据位置失败则删掉本次已写的数据位置 | 本卷事务提交。从卷随后跟上，不是写入时的法定人数 |
| 读和校验 | 读一份活副本。记录 CRC 和数据位置上的正文 CRC 对不上就换下一份 | 读卷时用 CRC。没有跨 zone 的对象副本可以换 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的数据位置。一份都不活记 `lost` | 从卷可以拿来恢复这一卷。不是按对象把缺少的一份补到第三台 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 写时复制。崩溃后从最后一致的卷状态继续 |
| 扩容 | 新 block 只接新写入。旧数据位置留在原节点 | 加的是卷或从卷。已有文件留在原卷里 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 快照留住某一刻的卷 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes`，超过就拒绝这个桶的 Put | 卷上可以压缩。配额不是 S3 桶配额 |
| 拷贝 | CopyObject 读出再写入 | 卷内可以做重复数据删除。拷贝可以共享块 |

## 修复与运维

| 项 | s3dfs | HAMMER2 |
| --- | --- | --- |
| 自我修复 | 活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的数据位置。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | CRC 能发现坏块，从卷可以用来恢复这一卷。没有默认定时把整卷读完并自动修好 |
| 自运维 | 探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧数据位置、缩容和重启只记下来。`lost` 写在 `$lost/`，重启后还在。未关闭的故障事件仍在进程内存里 | 快照、主从和换盘要人安排 |
| AI 辅助检查 | 规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有用模型读卷的状态 |
| 静默损坏巡检 | Get 时核对记录 CRC 和数据位置里的正文 CRC，不对就换一份副本。`scrub` 按数据位置重写坏副本并把检查数留在索引里，不把没有索引的 `.blk` 再读一遍 | 读时使用卷上的 CRC。没有公开的、默认定时全卷 scrub |
| 告警与升级 | 未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 复制落后和校验错误靠人看日志 |

## 和 s3dfs 的档

六种单机文件系统放在一起的表在 [主流位置](mainstream.md)。这一篇只留 s3dfs 和 HAMMER2。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 按规则自己做 | 按规则自己做 | 按规则自己做 | 要人来做 | 副本不够会再写一份，Get 时 CRC 不对就换一份。scrub 按数据位置留下计数，但没有把没有索引的 `.blk` 再读一遍。告警要配置地址才送出 |
| HAMMER2 | 按规则自己做 | 按规则自己做 | 要人来做 | 要人来做 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |

两边读的时候都核对校验。HAMMER2 没有默认定时把整卷读完并修好，从卷可以恢复这一卷。它仍是一台或少数几台机器上的盘，不提供跨 zone 的 S3。

还没做到修好后再核对、也还没交给值班直接用的部分见 [总表](summary.md)。

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | HAMMER2 |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的数据位置。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 快照留住这一刻的卷，新写入落到新块。从卷在另一台机器上跟上时，不用按文件把主卷再拷一遍 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 主从落后要人看。从卷不是同时可写的第三份。CRC 报错之后从主卷还是从卷恢复，要人定 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把数据位置写入索引。第 3 份可以稍后补。这次的数据位置没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 写时复制不覆盖仍被快照引用的块。提交的是这一卷的事务，不是跨三台机器的法定人数 |
| 读出来 | Get 按数据位置找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 卷上的 CRC 能发现坏块。没有第二台从卷时，发现了也没有另一份可换 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的数据位置。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 有快照就可以回到那一刻。快照不在了，删除就没有卷内的退路 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 写在 `$lost/`，重启后还在 | 只有主卷时，这台机器没了卷就没了。从卷在另一台，才扛得住这一台整机丢失 |
| 另一场地 | 默认不把对象送到另一套集群。桶上打开复制并配置了地址之后，之后的 Put 和 Delete 才送出。3 副本仍是这一套集群里的三台 block | 卷一级主从就是它的第二份。不建从卷，就没有另一场地 |

## 特色

| 只在 HAMMER2 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 卷一级主从 | 复制的单位是卷。从卷跟上主卷，不必按 key 把索引扫一遍再逐个 Get | 每个对象写到多台 block。索引里是一条条数据位置 |
| 快照留在卷上 | 某一刻的块还被快照引用，新写入落到新块 | 版本正文在 `$ver/`。没有整卷快照 |
| 卷内去重 | 相同的块可以只留一份，直到某一边被改写 | 没有去重。Copy 是读出再写入 |
| 卷上的 CRC 和压缩 | 校验和压缩是卷的属性，不是每个对象的数据位置字段 | CRC 在记录和数据位置上。压缩是写入时的默认 zstd |

## 留下的

整卷复制可以一次把数据目录带走，不必按 key 把索引扫一遍。快照让某一刻的卷还在，新写入落到新块。

## 不照搬的部分

主从卷不代替 3 台 block。去重和卷快照不进 S3 的默认路径。对象的唯一副本仍然按数据位置放在多台机器上。
## 总结

本篇用于整卷复制和按对象复制的选择。HAMMER2 以卷为主从单位，可以把某一时刻的卷留在快照中。s3dfs 以对象为复制和修复单位，三份副本分布在不同故障域的数据节点上。主从卷不计入这三份。

去重和卷快照不进入对象服务的默认路径。需要整目录一次带走时，应使用专门的备份流程，而不是把卷复制当作对象副本。

本篇不改变写成功条件和上线验收。跨故障域的保护以数据节点上的副本为准。
