MinIO 是一个 Go 进程上的 S3，对象按纠删集切到多块盘，元数据是每对象一份 `xl.meta`。s3dfs 把索引和正文分开，默认 3 份整对象打进 `.blk`。同一套纠删盘格式，MinIO 写在几千行的文件里；RustFS 用 Rust 重写了这条路径，单文件可以到四万行。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | MinIO |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存数据位置，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 一个 `minio` 进程同时做 S3 和磁盘。服务器代码几乎都在 `cmd/*.go`。元数据和分片落在同一套盘上，没有单独的小索引集群 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 纠删集上的数据片和校验片，外加该对象的 `xl.meta`。格式在 `cmd/xl-storage.go`、`cmd/xl-storage-format-v2.go`。bitrot 在 `cmd/bitrot.go` |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 对象哈希进某个纠删集，集内再落到各盘。位置不在另一套 KV 里 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的数据位置。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 写入纠删集，凑够写 quorum 才对外成功。池的实现在 `cmd/erasure-server-pool.go`，3005 行 |
| 一次读 | 先取数据位置，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。数据位置里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 凑够数据片即可读出。bitrot 对不上时用其余片解码。对象读写在 `cmd/erasure-object.go` |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和数据位置里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 分片上的 bitrot。读时核对，后台修复在 `cmd/erasure-healing.go`、`cmd/background-heal-ops.go` |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的数据位置覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 一个纠删集里的数据片加校验片，不是三份完整对象。集之间不共享故障预算 |
| 规模 | 每个可见对象至少一条数据位置，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 对象和版本对应盘上的元数据文件和分片。盘上的文件数随对象数涨。小对象会把目录项留给本地文件系统 |

## 标准对照

| 项 | s3dfs | MinIO |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 通用 S3。用纠删换容量，并带 IAM、桶策略、站点复制、对象锁和 KMS |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一组磁盘上的一个或一组 `minio` 进程。故障域是纠删集里的盘 |
| 元数据 | 每个对象一条数据位置 JSON（v:3），在 dleveldb。Get 先问索引 | 每对象一份 `xl.meta`，和数据片在同一套盘上 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。数据位置记节点和 `recId`，不记偏移 | 按纠删集切成片，写到各盘 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 调用方指定的桶和 key。放置由对象哈希决定 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 纠删。校验片能补上缺少的数据片 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条数据位置失败则删掉本次已写的数据位置 | 纠删集达到写 quorum。一个 pool 整体失去法定人数时，部署上的写入会停 |
| 读和校验 | 读一份活副本。记录 CRC 和数据位置上的正文 CRC 对不上就换下一份 | 凑够数据片，并核对 bitrot |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的数据位置。一份都不活记 `lost` | `cmd/background-heal-ops.go` 和 `cmd/erasure-healing.go` 用剩余片把缺的片写回去。片不够解码时对象读不出来 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 格式和提交在 `cmd/format-erasure.go`、`cmd/xl-storage-format-v2.go`。未完成的改名和元数据按盘上的格式恢复 |
| 扩容 | 新 block 只接新写入。旧数据位置留在原节点 | 在后面追加 pool。已有纠删集的宽度不改，旧对象留在原集 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/`。对象锁打开后可以写保留期、法律保全，桶上也可以给新对象一个默认天数 | 版本写在 `xl.meta`。对象锁、保留期和法律保全在同一条产品路径上 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes` | 服务端不默认把对象压小。桶配额在管理接口上 |
| 拷贝 | CopyObject 读出再写入。同集群可以先共享已有记录。送到另一套集群要另开复制规则，默认不送 | 服务端复制。站点复制在 `cmd/site-replication.go`，会把已有对象和之后的删除一起同步 |

## 代码量

同一口径：物理行，空行和注释都算，依赖目录不算。MinIO 是 `.go`，不含 `vendor`，合计 34.5 万行，其中 `*_test.go` 约 9.7 万，其余约 24.8 万。RustFS 是 `crates/` 与 `rustfs/` 的 `.rs`，不含 `target/`，约 207 万行。s3dfs 的 TypeScript 和 C 约 3.1 万行，不含 Markdown。

| | MinIO | RustFS |
| --- | --- | --- |
| 全部源码 | 34.5 万行 Go | 207 万行 Rust |
| 去掉测试文件之后 | 约 24.8 万。测试文件约 9.7 万 | 端到端测试另有 16.9 万。各目录里的单元测试还留在功能目录里 |
| 纠删和磁盘格式 | `cmd/` 里文件名前缀 `erasure` 1.7 万，`xl` 1.3 万，`storage` 1.1 万 | 纠删存储 56.5 万。修复和扫描还在另一类，合计 77.8 万 |
| 池的实现文件 | `cmd/erasure-server-pool.go` 3005 行 | `crates/ecstore/src/core/pools.rs` 43162 行 |
| 单盘读写 | `cmd/xl-storage.go` 3423 行 | `crates/ecstore/src/disk/local.rs` 41897 行 |
| 最大的单个文件 | `cmd/storage-datatypes_gen.go` 6933 行，是生成代码 | `pools.rs` 43162 行 |
| 分布式锁 | `internal/dsync` 约 0.3 万行 | `crates/lock` 1.8 万行 |

`cmd/` 里约 310 个实现文件、18.4 万行，按文件名前缀摊开。没有一个实现文件超过 7000 行。两边都自己写了纠删放置和 `xl.meta`，Go 里也没有一份现成的纠删对象存储库可以替 MinIO 少写这些文件。Go 标准库更厚，HTTP、JSON 和文件调用不用再包一层框架。这个差别到不了 3005 行和 43162 行的倍数。同一职责在 RustFS 里被写成了很长的单文件。

Reed-Solomon、CRC、HTTP 和序列化，Rust 都有库，RustFS 也接上了。没有库的是这种盘格式本身。库的有无说明这条路径要自己写，说明不了它比 MinIO 长出一个数量级。

上面 19 行相加是 205157。MinIO 长在自己写的盘格式、管理接口、复制状态和身份账本上。s3dfs 短在三份整对象、索引另放，以及 HTTP、CRC、AES 用 Node 自带的实现。

还有两块 s3dfs 有、这份 MinIO 树里没有对应目录。`apps/s3-gateway` 6222 行是用 C 再做一套 S3 入口，给要绕开 Node 的部署用。`apps/fuse` 3526 行把桶挂成目录，MinIO 这份树不提供挂载。MinIO 的对象位置写在 `xl.meta` 里，已经算进「纠删与盘」，所以它没有单独的索引进程。

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的数据位置。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 闭环。后台修复用剩余片把缺的片写回，入口在 `cmd/background-heal-ops.go` 和 `cmd/erasure-healing.go`。管理侧能看到修复，`cmd/admin-heal-ops.go`、`cmd/healingmetric_string.go`。片不够解码时不会编造正文 |

| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 手工。`cmd/metrics-v2.go` 提供指标，接到值班系统要人配。升级是替换二进制，没有自动跳版本 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。scrub 按数据位置留下计数，但没有把没有索引的 `.blk` 再读一遍。告警要配置地址才送出 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 的 scrub 覆盖没人读过的块。s3dfs 的 `scrub` 按数据位置修并留下计数，不扫没有索引的字节。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、KMS 和整集群的站点同步不在这张差距表里。身份账本、对象锁和桶复制开关已经有第一版。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把没有索引的 `.blk` 再读一遍。按数据位置的巡检已经会修并留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有在目标集群测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警只在配置了地址时送出，升级顺序已经写给值班，目标集群还没按这个顺序走过。本机 localhost 的通过不能当作唯一副本 |

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | MinIO |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的数据位置。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 一块盘掉了，只要纠删集还凑得齐，读和写可以继续。后台修复把缺的片写到还在的盘上。客户端仍用原来的 S3 地址 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 换盘、追加 pool、看一个 pool 是不是已经失去法定人数。站点复制、对象锁和 KMS 要单独配置。升级要人替换进程 |

## 哪些能放进 s3dfs

实现行 20.5 万里，有三笔性质不同。

纠删盘格式大约 4 万行：纠删与盘 25341，节点网格 6125，锁 3086，列举缓存 4722。这些行存在，是因为对象被切成片，名字和字节都在盘上，一次读要向多块盘要片，所以要互调、要抢锁、要在盘上做列表缓存。s3dfs 的名字在索引里，正文是整份记录。把这 4 万行搬过来，等于改掉现在的放置。

旧接口大约是通知、Select、分层、SFTP 和 FTP，再加上管理接口里只为 MinIO 自己的客户端准备的那一部分。社区版已经不维护。这些接口没有让数据更安全，只是让当时的客户端能连上。

第三笔是运维上比「只有 3 份副本」更完整的地方：一台节点离开、大对象加密、换密钥、用量、复制进度。这五点当前代码里已经有了。拿的是结果，不是那些 Go 文件。下面按这个分。

### 已经放进来的

身份账本在索引里：用户、组、策略、服务账号、`assumeRole`。Deny 压过 Allow，过期和停用都拒绝。根密钥和 `S3DFS_ACCOUNTS` 还在。桶可以默认 AES256，SSE-C 用调用方的密钥。复制是一个开关，打开后新的 Put 和 Delete 才送到另一套，默认关闭。通知是 webhook 加一个队列，事件里只有 bucket 和 key。对象锁可以给新对象一个默认保留期。`scrub` 按数据位置重写坏副本，并把检查数留在索引里。

这五点也已经在：

| 机制 | MinIO 为什么写了那么多 | 当前 s3dfs |
| --- | --- | --- |
| 一台节点离开 | 池退役要按纠删集重新编码，`erasure-server-pool-decom.go` 就有 1500 行以上。集的宽度不能变，所以搬走等于重写 | `drain(nodeId)` 从一份活副本再写到别的活节点，然后从数据位置去掉它。份数仍是配置的数。不调用就不动。`rebalance` 仍只往新节点复制 |
| 加密和上传是同一条路 | 封存做在对象流上，大对象不必先收进一个缓冲。`encryption-v1.go` 不长，长的是旁边的 KMS | 超过 1 MiB 且带 AES256 的 Put 按约 1 MiB 一块封存，Get 读出原文。未标明加密的对象仍是明文。不接 KMS |
| 密钥可以换 | `batch-rotate.go` 要改每条对象的片和 `xl.meta`，所以它是一个批任务 | 新封存头带密钥代号。当前密钥换成第二把、`S3DFS_SSE_KEY_PREVIOUS` 留着第一把时，旧对象仍能打开。没有代号的旧 `S3E1` 对象先试当前密钥，再试上一把。不因此重写 `.blk` |
| 用量是算完的数 | 名字在各块盘上，所以要 `data-scanner.go` 和 `metacache` 把列表和字节数做成缓存。缓存是为了少扫盘 | 名字已经在索引里。`bucketUsage` 按页扫完这个桶的数据位置，把可见对象的逻辑字节加总。`stats` 的对象数也不再停在 10 万条。不扫没有索引的字节 |
| 复制能看见进度 | `site-replication.go` 6284 行、`bucket-replication.go` 3803 行，是因为每一版、每一次标签和保留期修改都要记「送到没有」，两边还可以对写，还要补送已有对象 | `replicationProgress` 只给两个数：已送出多少条，`$chg/` 里还剩多少条。第一次 `sendChanges` 之前两个数都是 0。不补送已经在盘上的旧对象 |

这些都不要再做成 MinIO 的样子。身份不接 LDAP，也不走 `/minio/admin/v3`。复制不补送盘上的旧对象，也不给每个对象做一套状态。通知不改成旧的 XML，也不做 Listen。换密钥不接外部 KMS，也不把全部对象重写一遍。

### 不拿

一次 Get 如果必须让 block 互相调用，那就是纠删网格里的事。网格、分布式锁、盘上的列表缓存、`xl.meta` 都属于这一类。默认冗余继续是 3 份整对象。纠删能把可用容量从大约三分之一提高到大约七成，那是另一条产品，不是这一篇要补的洞。

只为了某个旧客户端的地址而存在的接口也不拿。FTP 和 SFTP 是第二套文件协议。`/minio/admin/v3` 是 MinIO 自己的管理客户端。Listen、Select、Glacier 取回、PostPolicy、对象 Lambda、四种消息队列、LDAP 和 OIDC 都是当时的产品面。身份和通知已经有自己的形状，不改去贴这些地址。

容量、片修复和「一个进程包办全部磁盘」是 MinIO 的选择。s3dfs 用索引换掉盘上的列表，用整份副本换掉片重建，用 Node 的 HTTP、CRC 和 AES 换掉再写一层库。上面那五点补的是离开一台、封存、换密钥、用量和复制进度，不是把 20.5 万行里剩下的文件再抄一遍。行数少是这个选择的结果。
