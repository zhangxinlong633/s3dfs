# 与 NFS 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要把目录挂到很多台机器上，同时又在看对象存储的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| NFS | 以 NFSv3、NFSv4 和 pNFS 的公开协议为准。服务器后面垫 CephFS、ZFS 或本地盘时，冗余是那一层的事 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 NFS 多出来的部分 |

NFS 把服务器上的一个目录树挂到客户端。客户端按路径和文件句柄读写字节。常见部署里，命名空间和磁盘都在这一台服务器上；写成功就是这台服务器的文件系统确认了。s3dfs 没有挂载，一次操作是一个 key。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | NFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 客户端通过 ONC RPC 调用服务器上的过程。服务器背后是它自己的文件系统。NFSv3 基本无状态。NFSv4 有会话、打开和租约。pNFS 才把布局和数据服务器分开 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 协议没有自己的块大小。READ 和 WRITE 的长度由一次 RPC 带多少字节决定。文件在服务器上是什么块，取决于服务器的本地文件系统 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | LOOKUP 或 OPEN 得到文件句柄。句柄是不透明字节，改名之后还可以指着同一个文件。客户端不解析句柄里的块号。NFSv4 的 stateid 只在打开和锁里使用 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | WRITE 的 stable 字段决定服务器要不要立刻落盘。FILE_SYNC 和 DATA_SYNC 在应答前落盘。UNSTABLE 只表示服务器收下了，客户端以后必须对同一段发 COMMIT。服务器在 COMMIT 前崩溃，这段可以丢 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | READ 用文件句柄和偏移。没有副本列表，也没有 CRC 字段。NFSv3 的常见约定是关闭之后别的客户端再打开，才能看见这次写。NFSv4 的委派可以让一个客户端暂时缓存 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 协议不规定数据校验。完整性是服务器文件系统的事。RPC 层可以有认证，那保护的是调用者身份，不是盘上的静默损坏 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 协议这一层没有副本。服务器导出的是它看见的一份目录树。pNFS 的布局可以把读写指到多台数据服务器，那些服务器上的冗余仍要另配 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 服务器的元数据随它自己的文件数涨。客户端不保存可重建索引。跟踪的状态在 NFSv4 上是打开和锁，租约过期就丢掉 |

## 标准对照

| 项 | s3dfs | NFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 多台机器共享一个目录树 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台 NFS 服务器加多个客户端。集群导出要另加一层，协议本身不复制文件 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 目录和属性在服务器上。客户端拿文件句柄，不拿块的位置 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 写进服务器本地的文件系统，或它背后的那一层存储 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 导出路径。NFSv4 有一个伪根，把多个导出接成一棵树 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 协议不规定副本。服务器只有一份时，服务器没了，挂载就断 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | `FILE_SYNC` 或 `DATA_SYNC` 要等服务器落盘。`UNSTABLE` 可以先放在服务器内存，客户端以后用 `COMMIT` 收口 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读服务器返回的字节。协议不带「换一份副本」的 CRC |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 服务器不可达，客户端就停在重试上。没有对象级的 `lost` |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 服务器起来后续上导出。NFSv4 的租约过期后，客户端的打开和锁要重做 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 一台服务器的盘满了，要换更大的导出，或改成 pNFS 那种把布局分到多台数据服务器 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 协议里没有对象版本。快照是服务器文件系统的功能 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 协议不压缩文件正文。配额在服务器的文件系统上 |
| 拷贝 | CopyObject 读出再写入 | 服务器端复制是后来的扩展。常见仍是客户端读出再写入 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | NFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 没有。协议不复制文件，也不在服务器丢了之后把缺失的字节补到另一台。客户端只会重试 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 在 API 进程内存里，重启从 0 再计 | 手工。导出、防火墙和服务器进程要人拉起。背后的文件系统若会自己修，那不是 NFS 的能力 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。没有用模型读导出或客户端的重试 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。没有把所有 `.blk` 再读一遍的 scrub | 没有。协议不巡检盘上的静默损坏 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。没有接上外部值班系统，也没有自动升级 | 手工。挂载失败留在客户端日志里。没有协议规定的告警和升级 |

## 省心与数据保护

这一节写值班的人和数据本身。上一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | NFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 客户端按挂载选项重试，服务器短时无响应时不用人逐台重新 mount。NFSv4 的委派让一个客户端的重复读少打到服务器。不用给每个读者单独发一份文件 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 导出列表、根权限、防火墙和服务器进程要人守。同步还是异步要人定。背后的盘是不是有冗余，NFS 不知道，也不会替人检查 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 同步写才表示已经进了服务器的盘。`UNSTABLE` 加上后来的 `COMMIT` 才收口。服务器在 `COMMIT` 之前崩溃，客户端手里的这段可以丢 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 没有 CRC，也没有第二台服务器可以换。读到的就是这一台返回的字节 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 在服务器上删了，所有客户端都没有了。能不能恢复取决于这台服务器的文件系统有没有快照，NFS 自己没有 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 重启后从 0 再计，盘上的丢失还在 | 服务器这台机器没了，全部分导出中断。协议里没有另一份可以接上 |
| 另一场地 | 没有把对象自动送到另一套集群、另一机房或一块备份盘。3 副本是这一套集群里的三台 block | 没有把导出复制到另一场地的步骤。备份是服务器上的另一个任务 |

## 特色

| 只在 NFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 不稳定写再 COMMIT | 客户端可以先把数据交给服务器，不要求立刻落盘。`COMMIT` 时服务器才保证这一段已经稳定 | 2 份 block 成功才写索引。没有「先对调用方成功、磁盘以后再承诺」 |
| 关闭才打开的一致性 | NFSv3 常见的约定是：关上文件之后，别的客户端再打开才能看见这次写。中间不保证字节实时一致 | Put 成功之后，随后的 Get 读索引里的这份 locator |
| 委派 | NFSv4 可以把一段文件暂时交给一个客户端缓存。别的客户端要写时，服务器把委派收回 | 没有客户端文件缓存的委派。Get 到的是当时的对象 |
| pNFS 布局 | 元数据服务器发一张布局，客户端按布局直接读写数据服务器。元数据服务器不转发每一段字节 | 索引发 locator，API 再向 block 要 `recId`。布局不是一张可以缓存的盘块地图 |
| 文件句柄 | 改名之后句柄还可以指向同一个文件。路径和身份是分开的 | key 就是身份。改 key 是另一次拷贝或删除 |

## 留下的

写成功要分清「服务器收下了」和「已经落盘」。只在需要立刻可见时才付出同步的代价，这个区分值得留在写路径的说明里。元数据确认之后，正文可以不经元数据服务转发。

## 不照搬的部分

s3dfs 的写成功仍是法定人数落盘之后写索引，不改成 NFS 的 `UNSTABLE` 写。不做目录挂载、文件句柄和委派。服务器背后那一层的副本不是 NFS 本身，不能拿「导出了一个目录」当成已经有 3 份对象。
