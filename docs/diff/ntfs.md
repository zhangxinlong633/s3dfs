# 与 NTFS 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 NTFS 的日志和主文件表里挑重启与审计的形状的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| NTFS | 以 Windows 的 NTFS 为准：`$LogFile`、MFT、USN 变更日志 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 NTFS 多出来的部分 |

NTFS 是 Windows 的本地文件系统。`$LogFile` 记元数据，崩溃后重放日志。很小的文件可以住在 MFT 记录里。USN 变更日志按顺序记下名字空间里发生了什么。s3dfs 的正文在 block，索引里只放 locator 和清单。

## 标准对照

| 项 | s3dfs | NTFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | Windows 本机文件。变更日志用来做增量备份和审计 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器上的一卷 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 主文件表（MFT）。元数据变更先进 `$LogFile` |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 足够大的文件在数据区。足够小的文件可以住在 MFT 记录里 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 目录里的文件名。改名记在 USN 里 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 文件系统自己不复制。冗余在磁盘或存储空间，不在 NTFS 的对象副本里 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 元数据事务写入日志。调用方看到的是提交之后的目录 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 不给每个用户数据块做端到端 CRC。坏扇区靠盘和上层存储 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | `chkdsk` 按日志和 MFT 修目录。没有跨机器的副本可换 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 重放 `$LogFile`。不把每个文件的内容再读一遍来恢复目录 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 卷可以扩大。已有文件留在原位置 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 卷影复制是 Windows 的另一层。NTFS 自己的 USN 记的是变化，不是某一刻的正文 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 文件压缩、稀疏文件、用户配额。不是按桶 |
| 拷贝 | CopyObject 读出再写入 | 普通文件拷贝。没有跨机器的对象克隆 |

## 特色

| 只在 NTFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| `$LogFile` | 元数据操作先记日志，崩溃后重放。目录和分配信息不必靠全盘扫描重建 | 没有一条只记元数据操作的重放日志。完整记录在 `.blk` 里，索引按法定人数写入 |
| 小文件住在 MFT | 足够小的文件放在自己的 MFT 记录里，少一次到数据区的寻道 | 再小的对象也进 `.blk`。版本正文在 `$ver/`，不放进索引 |
| USN 变更日志 | 按顺序记创建、改名、删除。日志里是事件，不是文件正文。增量备份和审计按这个顺序走 | 没有持久的「哪个 key 变了」日志。`lost` 在 API 进程内存里 |
| EFS 和稀疏文件 | 加密和空洞按文件设。稀疏文件不必把洞里的字节写满 | 一把 AES256，只覆盖放得进 1 MiB 缓冲的对象。没有稀疏对象 |

## 留下的

元数据日志让重启只重放目录和分配信息，不必扫描所有对象。变更日志只记「哪个名字变了、什么操作」，增量备份和审计按这个日志走，不把正文再写进日志。

## 不照搬的部分

小文件不住进索引。版本正文刚放到 block，就是为了索引里不要出现对象字节。USN 这种日志不在上线八项里；要做审计时再按「只记 key 和操作」来做。
