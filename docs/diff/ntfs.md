# 与 NTFS 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 NTFS 的日志和主文件表里挑重启与审计的形状的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| NTFS | 以 Windows 的 NTFS 为准：`$LogFile`、MFT、USN 变更日志 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 NTFS 多出来的部分 |

NTFS 是 Windows 的本地文件系统。`$LogFile` 记元数据，崩溃后重放日志。很小的文件可以住在 MFT 记录里。USN 变更日志按顺序记下名字空间里发生了什么。s3dfs 的正文在 block，索引里只放数据位置和清单。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | NTFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存数据位置，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 一卷里的主文件表（MFT）描述所有文件。$LogFile 只重放元数据，让崩溃后不必把每个文件的字节再读一遍。用户数据的副本不在这套结构里 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | MFT 记录常见 1 KiB。文件是记录里的属性。很小的文件可以住在记录里（驻留）。大了就变成非驻留，属性里是数据 run，指向簇。默认簇大小常见 4 KiB |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 目录是文件名属性的索引。文件号指向 MFT 记录。数据 run 里是卷上的簇号，没有集群节点加稳定记录号 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的数据位置。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 元数据修改先写 $LogFile 的重启区和重做记录，再改 MFT。提交之后崩溃，重放日志即可。文件正文的写不复制到第二块盘 |
| 一次读 | 先取数据位置，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。数据位置里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 按数据 run 读簇。没有每簇的端到端 CRC。USN 变更日志在 $Extend 下的 $UsnJrnl，记录的是文件号和原因码，不是文件正文 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和数据位置里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 没有父指针校验。静默损坏要靠盘或下面的存储空间。EFS 把加密放在文件属性里，密钥不在 MFT 里时可以单独丢 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的数据位置覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | NTFS 这一层没有第二份簇。镜像是卷下面的 RAID 或存储空间。USN 是事件序列，不是副本 |
| 规模 | 每个可见对象至少一条数据位置，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | MFT 随文件数涨，大约一文件一条记录。驻留文件会把正文也放进这条记录。这和索引里只放数据位置相反 |

## 标准对照

| 项 | s3dfs | NTFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | Windows 本机文件。变更日志用来做增量备份和审计 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台机器上的一卷 |
| 元数据 | 每个对象一条数据位置 JSON（v:3），在 dleveldb。Get 先问索引 | 主文件表（MFT）。元数据变更先进 `$LogFile` |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。数据位置记节点和 `recId`，不记偏移 | 足够大的文件在数据区。足够小的文件可以住在 MFT 记录里 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 目录里的文件名。改名记在 USN 里 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 文件系统自己不复制。冗余在磁盘或存储空间，不在 NTFS 的对象副本里 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条数据位置失败则删掉本次已写的数据位置 | 元数据事务写入日志。调用方看到的是提交之后的目录 |
| 读和校验 | 读一份活副本。记录 CRC 和数据位置上的正文 CRC 对不上就换下一份 | 不给每个用户数据块做端到端 CRC。坏扇区靠盘和上层存储 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的数据位置。一份都不活记 `lost` | `chkdsk` 按日志和 MFT 修目录。没有跨机器的副本可换 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 重放 `$LogFile`。不把每个文件的内容再读一遍来恢复目录 |
| 扩容 | 新 block 只接新写入。旧数据位置留在原节点 | 卷可以扩大。已有文件留在原位置 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 卷影复制是 Windows 的另一层。NTFS 自己的 USN 记的是变化，不是某一刻的正文 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes`，超过就拒绝这个桶的 Put | 文件压缩、稀疏文件、用户配额。不是按桶 |
| 拷贝 | CopyObject 读出再写入 | 普通文件拷贝。没有跨机器的对象克隆 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | NTFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的数据位置。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 规则自动。在线修复处理一部分元数据不一致，不必先卸载整卷。用户数据没有第二份对象副本可以换 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧数据位置、缩容和重启只记下来。`lost` 写在 `$lost/`，重启后还在。未关闭的故障事件仍在进程内存里 | 手工。`chkdsk`、卷影和配额由人安排。日志重放是启动时的规则，不是全套运维 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。NTFS 不用模型读主文件表或 USN |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和数据位置里的正文 CRC，不对就换一份副本。`scrub` 按数据位置重写坏副本并把检查数留在索引里，不把没有索引的 `.blk` 再读一遍 | 没有。用户数据没有端到端校验。USN 记的是变更，不是盘上的静默损坏 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 手工。事件查看器里有记录。升级随 Windows，不随这一卷自动进行 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。scrub 按数据位置留下计数，但没有把没有索引的 `.blk` 再读一遍。告警要配置地址才送出 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 的 scrub 覆盖没人读过的块。s3dfs 的 `scrub` 按数据位置修并留下计数，不扫没有索引的字节。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、KMS 和整集群的站点同步不在这张差距表里。身份账本、对象锁和桶复制开关已经有第一版。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把没有索引的 `.blk` 再读一遍。按数据位置的巡检已经会修并留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有在目标集群测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警只在配置了地址时送出，升级顺序已经写给值班，目标集群还没按这个顺序走过。本机 localhost 的通过不能当作唯一副本 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | NTFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的数据位置。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 启动时重放 `$LogFile`，不用把每个文件读一遍才把卷挂上。一部分元数据不一致可以在线修，不用先把整卷卸下来 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 用户文件的字节坏了，要人从备份恢复，卷不会从第二份对象副本里长出来。USN 只告诉备份软件哪些名字变了，备份软件和保留份数要人配。EFS 的密钥丢了，文件还在也打不开 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把数据位置写入索引。第 3 份可以稍后补。这次的数据位置没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 保护的是元数据事务：崩溃后目录和分配能收回一致。它不把文件正文复制到第二块盘 |
| 读出来 | Get 按数据位置找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 没有用户数据的端到端校验。读出来的字节就是这一卷上的字节 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的数据位置。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 回收站是文件管理器的行为，不是 NTFS 的一部分。卷影复制开着，才能回到上一刻的文件。否则删除就是删除 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 写在 `$lost/`，重启后还在 | 卷跟这块盘走。存储空间或 RAID 提供的镜像是卷下面的另一层，NTFS 自己不复制 |
| 另一场地 | 默认不把对象送到另一套集群。桶上打开复制并配置了地址之后，之后的 Put 和 Delete 才送出。3 副本仍是这一套集群里的三台 block | 另一场地是备份软件按 USN 做的增量。不配备份，变更日志只记着这件事发生过，字节没有第二份 |

## 特色

| 只在 NTFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| `$LogFile` | 元数据操作先记日志，崩溃后重放。目录和分配信息不必靠全盘扫描重建 | 没有一条只记元数据操作的重放日志。完整记录在 `.blk` 里，索引按法定人数写入 |
| 小文件住在 MFT | 足够小的文件放在自己的 MFT 记录里，少一次到数据区的寻道 | 再小的对象也进 `.blk`。版本正文在 `$ver/`，不放进索引 |
| USN 变更日志 | 按顺序记创建、改名、删除。日志里是事件，不是文件正文。增量备份和审计按这个顺序走 | Put 和 Delete 写 `$chg/`，记操作、bucket、key 和时间，不记正文。`lost` 写在 `$lost/` |
| EFS 和稀疏文件 | 加密和空洞按文件设。稀疏文件不必把洞里的字节写满 | AES256 按约 1 MiB 一块封存，上一把密钥留着时旧对象仍能打开。没有稀疏对象 |

## 留下的

元数据日志让重启只重放目录和分配信息，不必扫描所有对象。变更日志只记「哪个名字变了、什么操作」，增量备份和审计按这个日志走，不把正文再写进日志。

## 不照搬的部分

小文件不住进索引。版本正文刚放到 block，就是为了索引里不要出现对象字节。USN 这种日志不在上线八项里；要做审计时再按「只记 key 和操作」来做。
