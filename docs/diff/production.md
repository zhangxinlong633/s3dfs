# 上线标准

| | |
| --- | --- |
| 日期 | 2026-11-20 |
| 读者 | 决定某一套集群能否承接业务数据的人 |
| 效力 | 下表「验收」全部满足，且目标集群的演练笔记已记录，该部署可以保管本文所述负载的唯一副本 |
| 相关 | [部署](../deploy.md)、[规模说明](../scale.md)、[与主流系统的位置](mainstream.md) |

纠删码、IAM、KMS、Helm 不是本标准的前提。

## 1. 承接的负载

| 项目 | 要求 |
| --- | --- |
| 访问入口 | Nest S3 API，官方 AWS CLI 用 `--endpoint-url` 和路径风格直连。至少 2 台 API，前面是负载均衡 |
| 正文 | 3 台 block，分属 3 个 `@zone`。3 副本，2 份成功即对外成功，其余由修复补齐。`S3DFS_STRICT_LAYOUT` 保持开启 |
| 索引 | dleveldb 至少 3 个节点 |
| 身份 | 配置 `S3DFS_ACCESS_KEY` 与 `S3DFS_SECRET_KEY`。TLS 在反向代理上终止 |
| 对象 | 大量小对象，以及不超过配置上限的对象和分片 |

本机 localhost 数字不能用来定容量。

下列能力可以不做：把 C 网关暴露到公网、把 FUSE 当作性能路径、多租户、站点复制、Object Lock、配额、审计日志。网关若要与 API 一起对外，另见第 4 节。

## 2. 验收项

| 项 | 当前实现 | 验收 |
| --- | --- | --- |
| 正文副本 | 3 份里达到法定人数（默认 2）即写索引。一台 block 已标为 down、其余仍够法定人数和故障域时继续写。全部在线但节点或故障域少于配置份数时拒绝写入。修复去掉已停节点上的 locator；该节点恢复后再补回第 3 份。只剩 1 台时健康检查 503 | 停 1 台 block：新 Put 成功，Get 读到刚写的内容。修复后 locator 只指向仍在线的节点。该节点恢复并再次修复后回到 3 份。再停到只剩 1 台：新 Put 失败，`GET /_s3dfs/health` 为 503，正文含 `reasons` |
| 索引 | 主进程不可达时，偏好列表中第一个存活节点在剩余副本达到法定人数时接受写入。节点返回后按较新的 `mtime` 追平。仓库内三进程测试已覆盖该路径 | 在准备上线的 3 节点索引上再做一遍：停 1 个节点，Put 仍成功，另一台 API 能 Get 到同一对象。空节点追平后，已有对象仍能 Get 和 List。结果写入部署笔记 |
| 索引提交 | 达到法定人数后逐条写 locator。任一条失败则删除本次已写入的 locator。单元测试覆盖第二次写入失败后主键与 `:1` 均不保留 | 第二次索引写入失败时响应不是 2xx，随后 Get 为 404，索引中没有 `bucket/key` 和 `bucket/key:1` |
| 单次 Put | HTTP 入口把整个 body 收进 API 进程，默认上限 1 GiB | 上传大于 8 MiB 的对象时，API 堆内存的增长不超过缓冲上限的数倍。对象可读，ETag 规则不变 |
| 分片 | 清单留在索引。正文写入 block，key 为 `bucket/$upload/<id>/<part>`，列表和修复都不可见。完成时 API 仍把各段收成一个 Buffer 再 Put | 上传两段、重启 API、完成后再 Get，字节与逐段拼接一致。索引中不存在以分片正文为 value 的 `$upload/.../b/` |
| 丢失可见 | 修复把本次 `lost` 累加到进程内计数。计数大于 0 时健康检查 503，JSON 含 `lost`。进程重启后从 0 重新累加 | 构造一个全部副本不可读的对象并执行修复：健康检查 503，`lost` 至少为 1 |
| 入口 | 默认严格布局下，任一密钥缺失则进程在监听前退出。`pnpm dev:api` 设置 `S3DFS_STRICT_LAYOUT=0`，本机可不配密钥 | 不设置密钥、也不设置 `S3DFS_STRICT_LAYOUT=0` 时，进程退出且不监听。两个密钥都在时，无签名请求 403，签对的请求 200 |
| 容量 | 2026-11-17 与 2026-11-21 都是同一台笔记本上的 localhost。2026-11-21 补了 1 KiB 与 1 MiB 在 3 副本下的读写，见 [benchmarks.md](../benchmarks.md) | 在准备上线的机器和网络上再测 1 KiB 与 1 MiB、3 副本的写和读，写明日期和拓扑。本机数字不能用来定容量 |

## 3. 目标集群演练

代码项关闭之后，在准备承接流量的集群上执行下列步骤，把命令、时间和结果记入部署笔记。没有笔记，就不能把该集群当作唯一副本。

1. 三个 zone 均在线时，`GET /_s3dfs/health` 为 200，响应中 `layout.ok` 为真。
2. 停一个 zone 的 block，按「正文副本」一行做 Put、Get 和修复。停着的时候 locator 只指向仍在线的节点；该节点恢复并再次修复后回到 3 份。再停到只剩 1 台时，新 Put 失败，健康检查 503，正文含 `reasons`。
3. 停一个索引节点，按「索引」一行做 Put 和 Get。
4. 使用带密钥的客户端完成建桶、上传、分片上传、Range 读、删除和删除空桶。无密钥请求被拒绝。
5. 删除演练用的桶，确认没有留下 `lost`。健康检查回到 200。

## 4. 网关附加项

生产入口默认是 Nest API。C 网关要接到同一负载均衡后面，再满足三条：分片正文在 block 中且进程重启后仍在；`aws-chunked` 的分块签名与 Nest API 使用同一套校验；第 3 节演练改走网关再做一遍。

C 网关只认 `x-amz-date`、不认单独的 `Date`，不阻挡 Nest API 上线。
