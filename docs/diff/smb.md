# 与 SMB 的对照

| | |

| 日期 | 2026-11-21 |
| 读者 | 要从 Windows 文件共享里看租约、变更通知和多通道的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| SMB | 以 SMB2 和 SMB3 为准。连续可用和见证协议按微软的集群文件服务器来写。盘上的文件格式见 [ntfs.md](ntfs.md) |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 SMB 多出来的部分 |

SMB 把一台文件服务器上的目录共享给 Windows 和其他客户端。SMB3 加上加密、多通道和更明确的故障切换。调用方看见的是共享里的文件，不是 bucket。s3dfs 没有会话、没有打开句柄，也没有「这个文件正在被谁缓存」。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | SMB |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存数据位置，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 客户端先协商方言，再建立会话和树连接。SMB2 头固定 64 字节，协议号是 0xFE 加 SMB。SMB3 可以在外面再加一层变换头做加密。文件字节在服务器的文件系统里 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 一次读写的长度受协商出的信用（credit）和最大传输限制。服务器上的簇大小是背后那卷的事，SMB 不规定磁盘格式 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | CREATE 返回文件号和租约。路径只在打开时用。之后的读写用文件号。持久句柄把这个文件号的恢复信息和服务器上的打开绑在一起，切换之后可以重新接上 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的数据位置。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 写请求按服务器的稳定性处理。租约若允许缓存写，客户端可以先攒在本地，打破租约或刷盘时再送出。会话加密使用 SMB3 协商的算法，常见是 AES-128-CCM 或 AES-128-GCM。加密的是传输，不是第二份文件 |
| 一次读 | 先取数据位置，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。数据位置里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | READ 用文件号和偏移。租约可以让读留在客户端。别的客户端要冲突访问时，服务器先打破租约，再允许新的打开。没有 CRC 换副本 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和数据位置里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 签名防止传输被改。加密防止传输被看。两者都不核对盘上的扇区。盘上的校验是背后文件系统的事 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的数据位置覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 协议不复制文件。连续可用是另一台服务器接管同一个共享，后面通常是一块共享卷。见证协议通知客户端发生了切换。租约是缓存许可，不是副本 |
| 规模 | 每个可见对象至少一条数据位置，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 服务器的打开表随会话涨。文件元数据随背后那卷的文件数涨。SMB 本身不因为文件变多而增加索引集群 |

## 标准对照

| 项 | s3dfs | SMB |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 多台机器共享文件，尤其是 Windows 客户端 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一台文件服务器，或一组前面有共享存储的集群节点。协议不替每份文件做 3 副本 |
| 元数据 | 每个对象一条数据位置 JSON（v:3），在 dleveldb。Get 先问索引 | 目录、打开和租约在服务器的会话里。持久的是背后那卷文件系统 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。数据位置记节点和 `recId`，不记偏移 | 写进服务器的文件系统。SMB 负责传输、锁和缓存允许 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 共享名加路径 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 协议不复制文件。连续可用靠后面的共享卷和另一台服务器接管同一个共享 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条数据位置失败则删掉本次已写的数据位置 | 写请求在服务器按请求的稳定性处理完才应答。缓存写要等租约和刷盘的规则 |
| 读和校验 | 读一份活副本。记录 CRC 和数据位置上的正文 CRC 对不上就换下一份 | 读服务器给的字节。SMB 签名和加密保护的是传输，不是盘上的静默损坏 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的数据位置。一份都不活记 `lost` | 服务器没了，客户端重连。有见证协议时，集群会主动告诉客户端换一台 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 持久句柄可以在服务器切走之后重新接上。目录一致性靠背后的文件系统 |
| 扩容 | 新 block 只接新写入。旧数据位置留在原节点 | 扩大后面的那卷，或再加共享。已有文件不会因为多了一台 SMB 节点就分成对象 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 协议不提供 S3 版本。卷影复制是服务器一侧的快照 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes`，超过就拒绝这个桶的 Put | SMB 压缩是传输上的可选项。配额在文件服务器上 |
| 拷贝 | CopyObject 读出再写入 | 服务器端复制可以不把字节拉回客户端。不是对象存储的 Copy |

## 修复与运维

| 项 | s3dfs | SMB |
| --- | --- | --- |
| 自我修复 | 活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的数据位置。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 协议负责把已经打开的会话换到另一台服务器，不负责把损坏的文件从第二份副本修回来 |
| 自运维 | 探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧数据位置、缩容和重启只记下来。`lost` 写在 `$lost/`，重启后还在。未关闭的故障事件仍在进程内存里 | 见证协议通知客户端切换，持久句柄尽量接上。共享背后的卷、权限和备份仍要人管 |
| AI 辅助检查 | 规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有用模型读会话、租约或见证事件 |
| 静默损坏巡检 | Get 时核对记录 CRC 和数据位置里的正文 CRC，不对就换一份副本。`scrub` 按数据位置重写坏副本并把检查数留在索引里，不把没有索引的 `.blk` 再读一遍 | 签名和加密保护传输。盘上的静默损坏靠背后的文件系统 |
| 告警与升级 | 未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 集群切换有通知。文件服务器的升级和值班告警是 Windows 或管理员的流程，不是 SMB 自己的巡检 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | SMB |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的数据位置。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 见证协议在集群切换时通知客户端，应用尽量不用重开已经打开的文件。多通道不用人在每台客户端上手工绑会话。租约让重复读留在客户端 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 共享权限、要不要会话加密、卷影复制开不开，都要人配。见证和持久句柄依赖后面有另一台服务器和共享卷。只有一台机器时，没有自动接管 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把数据位置写入索引。第 3 份可以稍后补。这次的数据位置没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 写进这台文件服务器的卷。SMB 加密和签名保护的是网络上的篡改，不是第二块盘上的副本 |
| 读出来 | Get 按数据位置找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 没有另一份文件副本可以换。读出来的字节靠背后那卷 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的数据位置。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 卷影复制开着，才能取回上一刻的文件。没开卷影时，删除就是删除。回收站同样不是协议的一部分 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 写在 `$lost/`，重启后还在 | 连续可用要求共享存储和另一台节点已经配好。只开了 SMB 的一台机器没了，共享就没了 |
| 另一场地 | 默认不把对象送到另一套集群。桶上打开复制并配置了地址之后，之后的 Put 和 Delete 才送出。3 副本仍是这一套集群里的三台 block | 协议不把共享送到另一机房。另一场地是 DFS 复制或备份软件，要另外部署 |

## 特色

| 只在 SMB 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 租约 | 服务器允许一个客户端缓存读或缓存写。别的客户端要冲突访问时，先打破租约 | 没有打开文件的租约。Put 成功后的 Get 看索引 |
| 变更通知 | 客户端可以订一个目录，服务器在里面的文件变化时推送 | 没有目录变更推送。一个 webhook 只在已经接上的事件上 |
| 多通道 | 一个会话可以同时用多条 TCP 或 RDMA 连接，打满多块网卡 | 一个请求走一条到 API 或 block 的连接。没有会话级多通道 |
| 加密和签名 | SMB3 可以给整个会话加密。签名防止传输被改 | 传输用 HTTPS 是部署的事。对象上的 AES256 按块封存正文，和 SMB 会话加密不是同一层 |
| 见证和持久句柄 | 集群文件服务器切换时，见证协议通知客户端，持久句柄尽量不断开应用已经打开的文件 | API 无状态。客户端重试 Put 或 Get。没有「打开着的文件」可以迁到另一台 API |

## 留下的

缓存许可能不能一直留在客户端，要有人在冲突时把它收回。变更可以按「哪个名字变了」推给订阅者，而不把正文再送一遍。一台服务器切换时，最好由集群通知客户端，而不是只靠客户端超时。

## 不照搬的部分

s3dfs 不做 SMB 共享，也不做打开句柄和租约。会话加密不代替对象副本。连续可用依赖的是后面那块共享盘，不能当成已经有跨 zone 的 3 份对象。变更通知留到审计或增量复制真的要做时再按 key 记，不在上线八项里。
## 总结

本篇用于文件共享和对象服务的边界。SMB 提供打开文件、租约和会话加密，切换时通知客户端。s3dfs 不维持打开句柄，加密作用在对象正文，副本是跨故障域的三份完整数据。

变更可以只记录对象名和操作，不在日志中保存正文。这一能力用于审计和增量复制的形状，不替代对象副本，也不列入当前上线八项。

Windows 文件共享继续由 SMB 承担。对象业务的可用性以数据节点和索引的法定人数为准，不以会话能否接上为准。
