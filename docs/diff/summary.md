s3dfs 默认是 3 份整对象，3 份里 2 份落盘才写索引，名字在 dleveldb，正文打进约 1 GiB 的 `.blk`。key 由调用方指定。读一份活副本，CRC 不对再换。`lost` 写在 `$lost/`。身份、对象锁、桶配额、默认 AES256、SSE-C、按块封存、换密钥、桶复制开关、通知、`drain`、用量和复制进度都已有第一版。纠删、KMS、LDAP 和整集群的站点同步没有。

## 放置上的不同

这些是选择。容量大约是裸盘的三分之一。纠删那一档大约能卖出七成，那是另一条产品。

| 我们 | 别人 |
| --- | --- |
| 3 份整对象，2 份成功即写索引 | MinIO、RustFS、Ceph 数据池、SeaweedFS 温数据用纠删。GFS、TFS 要每一份都确认。FastDFS 往往一台落盘就返回 |
| 索引和 block 分开。每次 Get 先问索引 | MinIO、RustFS 把名字和片放在同一套盘的 `xl.meta` 里。SeaweedFS 的 master 不在读路径上。TFS 可以把块位置编进文件名 |
| 读一份，坏了再换 | Garage `consistent` 要两份元数据对上才回答。纠删要凑够数据片 |
| 加机器之后旧数据位置留在原节点。`drain` 要人调用 | Btrfs 的 balance、Ceph 的 CRUSH 会搬旧数据。MinIO 追加 pool，旧对象留在原集 |
| 入口是 S3。key 由调用方指定 | GFS、TFS、FastDFS、单机文件系统、CephFS、NFS、SMB 管的是文件或目录。Ceph Block 和 Longhorn 给的是一块盘 |

## 还没对齐的差距

档次仍是规则自动。闭环和产品没有升。下面这些不因为某一篇里别人有，就改成纠删或再抄一套旧接口。

| 差距 | 现在 | 别人有、我们还没有 | 关闭条件 |
| --- | --- | --- | --- |
| 没人读过、也没有索引的字节 | `scrub` 按数据位置重写坏副本，检查数留在索引里 | ZFS 的 scrub、Ceph 的 deep-scrub 把没人读的块也走一遍 | 把没有索引的 `.blk` 再读一遍。不因此改成 RAID-Z |
| 恢复要多久 | 仓库里没有这个时间 | ZFS 的 resilver 有进度 | 目标集群上停一台 block、停一台索引，记下健康检查回到 200 的时间和当时的 JSON |
| 上线容量 | 只有本机 localhost 的 1 KiB 与 1 MiB、3 副本 | 各家数字来自他们自己的机器，不能拿来减 | 在准备上线的机器和网络上测出这两个尺寸，写入基准文档 |
| 目标集群演练 | 本机演练已有笔记 | 上线以那套集群自己的故障演练为准 | 准备承接流量的集群走完五步，命令、时间和结果写入部署笔记 |
| 生产部署 | 脚本在仓库里 | 别人的集群是已经装上并在跑的 | 准备接流量的环境按部署文档装完，`GET /_s3dfs/health` 为 200 |
| 整集群同步 | 桶上打开复制后，之后的 Put 和 Delete 才送出。已送和未送是两个数。不补旧对象 | MinIO、RustFS 的站点复制会同步已有对象，并按对象记住送到没有 | 不作为上线前提。要做也只是补送，不改成纠删后再复制 |
| 外部密钥 | 封存头带密钥代号。上一把留在 `S3DFS_SSE_KEY_PREVIOUS` 时旧对象仍能打开 | MinIO、RustFS 接到 Vault 或云上的 KMS | 不接外部 KMS，也不因此重写全部 `.blk` |
| 目录和身份源 | 索引里有用户、组、策略、服务账号和 `assumeRole` | MinIO、RustFS 另有 LDAP 和 OIDC | 不接 LDAP 和 OIDC |
| 加密的分片完成 | 未加密的完成按段转发。带服务端加密时仍拼成一段再封口。`aws-chunked` 仍整段读入 | 网关按段提交，不在一个进程里拼出整个对象 | 不挡上线八项 |

告警只在配置了 `S3DFS_ALERT_URL` 时送出。升级顺序已经写给值班，目标集群还没按这个顺序走过。未关闭的故障事件仍在进程内存里。

## 按对照

| 对照 | 不同 | 差距 |
| --- | --- | --- |
| [MinIO](minio.md) | 一个进程上的纠删 S3，元数据是每对象一份 `xl.meta`。我们是三种进程、3 份整对象 | 站点补送、KMS、LDAP、Prometheus 和盘上列表缓存仍没有。拆节点、按块封存、换密钥、用量和复制进度已经有了 |
| [RustFS](rustfs.md) | 用 Rust 重写了 MinIO 那条盘格式，正式源码长一个数量级 | 同一批不拿：纠删、KMS、LDAP、Select、SFTP、Helm。身份、对象锁、配额、加密和桶复制已有第一版 |
| [Garage](mainstream.md) | 一个二进制，3 份里读写法定人数都可以是 2 | 我们读一份。没有他们那种跨站点的放置。身份账本已有，整集群同步没有 |
| [SeaweedFS](mainstream.md) | 热数据每一份都要写成功，master 不在读路径上。温数据才纠删 | 我们写 2 份即成功，每次 Get 先问索引。缺的份会补。卷位置缓存没有 |
| [Ceph RGW](mainstream.md) | 桶索引复制，数据池常用纠删，OSD 掉了靠 backfill | 我们不用 CRUSH 搬旧对象，也不把数据池改成纠删。元数据和正文分开这一点相同 |
| [CephFS](cephfs.md) | MDS 管目录，客户端直接读写 OSD | 我们没有 POSIX、硬链接和客户端能力缓存。配额边界是桶，不是目录 |
| [Ceph Block](ceph-block.md) | 镜像切成 RADOS 对象，写到 `min_size` 即成功 | 我们不做块设备和偏移读写。写成功同是多数，拷贝仍是对象 Copy |
| [GFS](gfs.md) | 一个 master 记 chunk 位置，写要每一份都确认 | 我们的写是法定人数。key 不能改成 chunk 句柄，所以 Get 仍问索引 |
| [TFS](tfs.md) | 小文件并进块，文件名由系统编出块号 | 我们的 key 由调用方指定。块是复制单位这一点已经相同，写不等齐 3 份 |
| [FastDFS](fastdfs.md) | tracker 不存每文件索引，同组靠 binlog 异步推 | 我们不在只落下一份时返回。故障域按最紧的盘记账已经有了 |
| [Longhorn](longhorn.md) | Kubernetes 里的卷，副本是节点盘上的快照链 | 修复单位仍是对象。全部副本没了会记 `lost`，这一点相同 |
| [ZFS](zfs.md) | 一台机器上的池。校验和在父指针里，scrub 走完没人读的块 | 我们的 `scrub` 只走有数据位置的对象。快照和 RAID-Z 不替换 3 副本 |
| [Btrfs](btrfs.md) | 单机写时复制。加盘后用 balance 搬匀 | 我们加 block 不自动搬旧数据位置。`drain` 是另一次调用 |
| [HAMMER2](hammer2.md) | 卷上做写时复制、快照和主从 | 主从卷不代替 3 台 block。没有整卷一次带走 |
| [APFS](apfs.md) | 一个容器里多个卷共享剩余空间，克隆先改元数据 | 同集群 Copy 可以先共享记录。用户数据的 CRC 仍在记录和数据位置里 |
| [NTFS](ntfs.md) | `$LogFile` 重放元数据，USN 只记名字变了 | `$chg/` 记操作、bucket、key 和时间，不记正文。小文件不因此写进索引 |
| [FFS](ffs.md) | 软更新按依赖恢复元数据。GEOM 在文件系统下面叠镜像 | 镜像和校验已经在 API 下面的索引和 block 上。软更新不放进 dleveldb |
| [NFS](nfs.md) | 导出目录。`UNSTABLE` 可以先收在内存里，再 `COMMIT` | 写成功仍是法定人数落盘后再写索引。没有挂载和文件句柄 |
| [SMB](smb.md) | 文件共享。切换时通知客户端，会话可以加密 | 不做打开句柄和租约。对象加密是正文封存，不是会话加密 |
