# 与 TFS 的对照

| | |

| 日期 | 2026-11-21 |

| TFS | 以淘宝公开材料为准：InfoQ 对楚材的访谈、架构说明，以及开源仓库 alibaba/tfs 的文件名和运维工具。材料年代大约在 2010–2014 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 TFS 多出来的部分 |

TFS（Taobao File System）给淘宝的商品图、描述和交易快照用。单个文件通常不超过 1 MiB，数量很大。它把小文件并进块，NameServer 只记块在哪。s3dfs 也把小对象打进大 `.blk`，位置放在索引里，因为 S3 key 由调用方指定。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | TFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 两个 NameServer 一主一备，只记块在哪些 DataServer 上。小文件的偏移在 DataServer 的块索引里。客户端解出块号之后可以直接找 DataServer |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 块大小可配，公开材料里常见 64 MiB。块号集群内唯一。块内每个小文件一条索引，DataServer 启动时尽量把这些索引放进内存 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 文件名由客户端编出来，最长约 18 字节，以 T 开头，里面是集群号、块号和文件号。convert_name 与 reverse_name 做转换。名字本身就是第一级定位，NameServer 不存每个文件一行 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | NameServer 分配或指定块，并给出持有这块的 DataServer。一块同时只有一个写。公开材料要求参与的每一台都写完，master DataServer 才向 NameServer 和客户端报成功。常见是 3 份，放在不同网段 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 从文件名解出块号和文件号。有块位置缓存就直接读 DataServer 的块索引；没有就问 NameServer。CRC 不匹配就换另一份块 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | CRC 在 DataServer 读路径上核对。块和 DataServer 的对应关系靠心跳重建，不靠文件名里的机器地址。文件名里有块号，没有某一台机器的固定地址 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 复制单位是整块，不是单个小文件。一块的 3 份要一起写完。文件变长时用扩展块链出去，不在原记录里把文件撑大 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 1 PB、64 MiB 一块大约一千六百万块。按每块约 0.1 KiB 估算，NameServer 不到 2 GB。小文件条数涨在 DataServer 的块索引里，不涨在 NameServer |

## 标准对照

| 项 | s3dfs | TFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 海量小文件，多数是图片。系统在写入时发一个短文件名 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 两个 NameServer 一主一备，多个 DataServer。另可有只读的辅集群 |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | NameServer 只记块在哪些 DataServer 上。块内每个小文件的位置在 DataServer 自己的块索引里 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 并进块。块大小可配，常见 64 MiB。块号由 NameServer 分配，集群内唯一 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 客户端把集群号、块号、文件号编成文件名，最长约 18 字节，以 `T` 开头 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 一块常见 3 份，公开材料写分布在不同网段 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 参与的每一台 DataServer 都写完，master DataServer 才向 NameServer 和客户端报成功 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 从文件名解出块号和文件号。CRC 不匹配就换另一份块 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | NameServer 发现份数不够就复制块。心跳里 DataServer 上报自己有哪些块，用来重建映射 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | DataServer 启动时把块索引尽量装进内存。NameServer 用心跳重建块到机器的映射 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 新 DataServer 心跳加入。新写入偏向更空的机器。空闲时按块均衡，移动尽量留在同一网段 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 没有 S3 版本。辅集群靠重放主集群的操作，接近一份只读拷贝 |
| 压缩与配额 | 默认 zstd，压不小则存原文。没有桶配额 | 公开材料不把压缩和桶配额当存储系统的一部分 |
| 拷贝 | CopyObject 读出再写入 | 按块复制。调用方拿的是系统编出来的文件名 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | TFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 规则自动。NameServer 发现块的份数不够就复制块。公开材料没有写修复之后再读一遍确认，也没有恢复时间上限 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 在 API 进程内存里，重启从 0 再计 | 规则自动。心跳重建块的位置，空闲时按块均衡。换盘、机房和辅集群仍要人安排 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。公开材料不用模型读 NameServer 或 DataServer |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。没有把所有 `.blk` 再读一遍的 scrub | 规则自动。读时 CRC 不匹配就换另一份块。没有写成独立产品的全量巡检 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。没有接上外部值班系统，也没有自动升级 | 手工。运维工具在开源仓库里，告警和升级没有交给一套值班产品 |

## 省心与数据保护

这一节写值班的人和数据本身。上一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | TFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | DataServer 用心跳报告本机有哪些块，NameServer 用这个补映射和缺的副本。客户端缓存了块在哪，NameServer 短时不可达，已经知道位置的读还可以继续。CRC 不对就换另一份块 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 主 NameServer 和备机谁在接写，要人确认。辅机房的重放延迟要单独看。按块均衡尽量留在同一网段，跨网段搬要人看带宽。文件名丢了，块号就无从解出，图就找不到 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 公开材料里一份块要参与的每一台 DataServer 都写完才对客户端成功，一块同时只有一个写。保护的是不会只在一台盘上就返回。慢的那一台会拖住写 |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 从文件名解出块号和文件号，再按块内索引取字节。CRC 不匹配就换另一份块 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 删除记在块上，空间由清理任务回收。没有版本。误删要靠业务还留着的文件名，以及业务自己的备份 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 重启后从 0 再计，盘上的丢失还在 | 丢一台 DataServer，块还有别的副本就复制。NameServer 主备切换要人演练。块的三份如果被放在同一台机器或同一块盘上，这台没了就没有可复制的源 |
| 另一场地 | 没有把对象自动送到另一套集群、另一机房或一块备份盘。3 副本是这一套集群里的三台 block | 辅集群重放是材料里的只读另一场地。不搭辅集群，就只有这一边的块副本 |

## 特色

| 只在 TFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 文件名里带位置 | `convert_name` / `reverse_name` 在短名和块号、文件号之间转换。客户端有块位置缓存时，读可以不问 NameServer | key 里不能放块号。每次 Get 都问索引，再按 `recId` 找 block |
| 一级索引按块 | 1 PB、64 MiB 一块，大约一千六百万块。按每块 0.1 KiB 估算，NameServer 内存不到 2 GB。小文件的条数不决定 NameServer 的内存 | 索引按对象。对象数量决定 dleveldb 里的 locator 条数。块文件数跟 `.blk` 走，不跟对象数走 |
| 一块同时一个写 | 一个块在某一时刻只允许一个写入者，避免块内索引互相覆盖 | `.blk` 由本机引擎追加。对象之间不抢同一条块内索引 |
| 主块加扩展块 | 文件变长时，原块放不下就链到扩展块 | 覆盖是新的记录和新的 locator。不在原记录里把对象写长 |
| 主辅集群重放 | 主集群把操作重放到只读辅集群，用来做机房级的另一份 | 没有这条重放。冗余是同一个对象的 3 份 block |

## 留下的

块是复制、均衡和修复的单位，小文件只是块里的一条记录。块位置可以缓存，读路径不必每次都问中心节点。名字里如果带得下位置，中心节点就不必为每个小文件留一条记录。

## 不照搬的部分

S3 key 不能改写成 18 字节文件名，所以每次 Get 仍要问 dleveldb。写成功保持法定人数，不等齐 3 份。不另做主辅机房的操作重放。
