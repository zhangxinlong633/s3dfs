# 与 ZFS 的对照

| | |
| --- | --- |
| 日期 | 2026-11-21 |
| 读者 | 要从 OpenZFS 里拿校验、巡检和快照，同时继续用跨机器的 3 副本的人 |
| s3dfs | 以当时仓库的 [架构](../architecture.md)、[能力](../capabilities.md) 为准 |
| ZFS | 以 OpenZFS 的池、数据集、RAID-Z、scrub、send/recv 为准。Sun 的 ZFS 和现在的 OpenZFS 是这一系 |
| 怎么读 | 标准对照的项目和 s3dfs 列，与本目录其他文件系统对照相同。特色只写 ZFS 多出来的部分 |

ZFS 把文件系统和卷管理放在一台机器的池里。镜像或 RAID-Z 提供冗余，校验和放在父指针里，scrub 走完整池，快照和 `zfs send` / `recv` 做某一刻的复制。s3dfs 的冗余在多台 block 上，每台机器上的 `.blk` 只是追加的记录文件。块设备上可以跑 ZFS，那是机器自己的事，不是 s3dfs 的副本。

## 原理与细节

标准对照只对齐结论。这里写出结论从哪条原理来，以及能对上的字节、步数和规模。s3dfs 这一列在本目录各份对照里相同。

| 点 | s3dfs | ZFS |
| --- | --- | --- |
| 分层 | 三种进程。dleveldb 只存 locator，block 里的 C 引擎只追加记录，API 不打开本地盘。对象变多，增加的是 KV 条数和少量大文件，不是一对象一文件 | 一个存储池把文件系统和卷管理放在一起。数据在 vdev 上，逻辑数据集在池里面。没有单独的跨机器索引集群 |
| 磁盘上的单位 | `blocks/` 下的文件名是 20 位块号加 `.blk`，默认 1 GiB。记录小端，魔数 `S3R1`（`0x31523353`）。帧依次是 magic u32、rec_len u32、tags、crc32 u32，再重复 rec_len u32 和 magic u32，开销 20 字节。标签依次是 type u16、length u32、value。不认识的标签跳过。`recmap.s3m` 魔数 `S3M1`，只是重启缓存；末尾 4 字节 CRC 对不上就重扫 `.blk` | 默认 recordsize 128 KiB，可按数据集改。指针是 blkptr，里面最多三个数据虚拟地址（DVA）、出生事务组号和校验和。事务按事务组提交，崩溃后回到上一组已提交的指针 |
| 名字怎么找到字节 | 索引值是 JSON，`v` 为 3。第 0 份的键是 `bucket/key`，第 i 份（i≥1）是 `bucket/key:i`。里面有 `nodeId`、`address`、`recId`，没有文件偏移。`recId` 是标签 `0x000E` 的 u64。compact 可以改块号和偏移，不改 `recId` | 路径解析走到对象集和 dnode，再走到 blkptr。blkptr 里的 DVA 就是这一块现在的物理位置。快照保留旧的 blkptr，所以旧块不会被覆盖 |
| 一次写 | 默认 3 份，法定人数是多数：3 份里要 2 份。同一段字节写到不同 `@zone`。引擎把记录追加进当前 `.blk`，写缓冲默认 1 MiB，flush 默认 fsync。凑够 2 份才写索引；没凑够就删掉这次已写的 locator。放得进缓冲的对象默认 zstd，压不小则 `compressType=none`。超过 1 MiB 的原始 Put 按 1 MiB 交给 block，这种对象不压缩 | 同步写先记意图日志（ZIL），再在后面的事务组里归入池。新块写到新的位置，然后用一次指针替换让它可见。读者不会看到写了一半的块。这不把同一次写复制到另一台机器 |
| 一次读 | 先取 locator，跳过 down 的节点，按 `recId` 取记录。记录上的 CRC 是键字节接上正文。locator 里的 `crc` 是压缩前正文的 CRC-32。对不上就试下一份。链式对象用标签 `0x0006` 的 `PREV` 指向上一条 extent 的 `recId`，最后一段 kind 为 3 | 沿着 blkptr 读数据块，用指针里的校验和核对读到的字节。对不上且有冗余，就用镜像或 RAID-Z 里对得上的那一份把坏块改写好 |
| 校验放在哪 | 帧内 CRC-32 覆盖前 8 字节加全部标签，初值按 `crc32_update(0, …)` 计算，算法是 CRC-32/ISO-HDLC，反射多项式 `0xEDB88320`，与 zlib.crc32 相同。正文 CRC 另记在标签 `0x0004` 和 locator 里。kind：1 单条对象，2 中间 extent，3 最后一段，4 墓碑 | 校验和在父指针 blkptr 里，不在数据块自己的末尾。算法可配。普通数据常用 Fletcher-4；打开去重时改用更强的校验。盘若返回一段自洽但错误的块，父指针对不上 |
| 副本是什么形状 | 三份是同一段逻辑字节的三份完整记录，不是条带，也不是纠删片。没有主副本。后写的 locator 覆盖先写的。删除先写 kind 4 的墓碑，避免扫描把已删对象救回来 | 镜像是同一块的两份或三份。RAID-Z1/2/3 是变长条带加 1 到 3 份校验，避免传统 RAID-5 那种对部分条带的读改写。冗余都在这一个池的 vdev 里 |
| 规模 | 每个可见对象至少一条 locator，3 副本是 3 条键。`.blk` 的个数约等于字节数除以 1 GiB。单进程活记录停在 2^30−1。索引按 key 涨，不按块涨 | 元数据随块和文件涨，在池自己的对象集里。不存在每个小文件一条中心索引、中心内存按文件数线性涨这一层。数据集、快照和空间图是池内的对象 |

## 标准对照

| 项 | s3dfs | ZFS |
| --- | --- | --- |
| 它解决什么 | 大量小对象的 S3。key 由调用方指定 | 一台机器上的文件和卷，自己发现静默损坏，并按数据集做快照和配额 |
| 跑在哪 | 多台机器。API、dleveldb 索引、block 三种进程。故障域是 block 上的 `@zone` | 一个池。池不跨 s3dfs 这种 zone |
| 元数据 | 每个对象一条 locator JSON（v:3），在 dleveldb。Get 先问索引 | 对象集、数据集和目录都在池里。指向数据块的指针带着下一块的校验和 |
| 正文 | 追加进约 1 GiB 的 `.blk`。记录是 `S3R1` TLV。locator 记节点和 `recId`，不记偏移 | 写时复制的块。新块写完，再把指针从旧块改到新块 |
| 名字 | `bucket/key`。第 i 份（i≥1）在 `bucket/key:i` | 池里的路径。快照名挂在数据集上 |
| 冗余 | 默认同一份对象 3 份，落在不同 zone | 池内镜像，或 RAID-Z1/2/3。冗余的是块，不是跨机器的对象副本 |
| 写成功 | 3 份里 2 份 block 成功即写索引。第 3 份由修复补。任一条 locator 失败则删掉本次已写的 locator | 事务把新块写完并更新指针。读者看不到写了一半的块 |
| 读和校验 | 读一份活副本。记录 CRC 和 locator 上的正文 CRC 对不上就换下一份 | 读块时用父指针里的校验和核对。对不上就用冗余副本修好这一块 |
| 损坏之后 | 健康检查跳过 down 节点。`repair` 把不足的份数补到仍在线的节点，并去掉 down 的 locator。一份都不活记 `lost` | 缺盘之后 resilver 把冗余重建到新盘。这和把整池再读一遍的 scrub 是两件事 |
| 崩溃恢复 | `.blk` 里只承认完整记录。索引按法定人数写入。`recmap.s3m` 只是重启缓存，坏了就重扫 `.blk` | 写时复制加上事务组。崩溃后从最后一组一致的指针继续 |
| 扩容 | 新 block 只接新写入。旧 locator 留在原节点 | 向池里加盘。已有数据要靠单独的搬迁才会到新盘上 |
| 某一刻 | 版本清单在索引，正文在 block 的 `$ver/` | 快照几乎只增加一组仍被引用的块。`zfs send` / `recv` 复制快照之间的差 |
| 压缩与配额 | 默认 zstd，压不小则存原文。桶上可以设 `quotaBytes`，超过就拒绝这个桶的 Put | 按数据集开压缩。数据集上有配额和预留 |
| 拷贝 | CopyObject 读出再写入 | 克隆共享快照的块，直到某一边被改写 |

## 修复与运维

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。档写在每格开头。

| 项 | s3dfs | ZFS |
| --- | --- | --- |
| 自我修复 | 规则自动。活副本不足时，周期任务或 `POST /_s3dfs/repair` 再写一份，并去掉指向 down 节点的 locator。一份都不活就记 `lost`，健康检查失败，不编造正文。没有测过恢复时间上限 | 闭环。读到父指针校验失败，有冗余就修好这一块。缺盘后 resilver 把数据补到新盘。修完的结果留在池的错误计数里 |
| 自运维 | 规则自动。探活、flush、compact、repair 按周期跑。巡检规则在副本不足、空洞过高或有未落盘字节时执行对应动作；配置了扩容命令且负载持续高时才扩容。换盘、搬走旧 locator、缩容和重启只记下来。`lost` 写在 `$lost/`，重启后还在。未关闭的故障事件仍在进程内存里 | 规则自动。scrub 可以按计划跑，事件守护进程可以通知换盘。换哪块盘、池怎么扩，仍要人确认 |
| AI 辅助检查 | 手工。规则先做维护。本机模型只把七个模块的数字写成中文结论，并留下能和上一轮比较的 HTML。模型不读对象正文，不删除，不重启，不缩容。关掉模型时规则简报还在。模型不决定修不修 | 没有。池的状态和 scrub 报告是规则产物，不是模型结论 |
| 静默损坏巡检 | 规则自动。Get 时核对记录 CRC 和 locator 里的正文 CRC，不对就换一份副本。`scrub` 按 locator 重写坏副本并把检查数留在索引里，不把没有索引的 `.blk` 再读一遍 | 闭环。scrub 把池再读一遍，能修的就修，和「缺盘之后再补」分开 |
| 告警与升级 | 手工。未恢复事件进巡检决定，简报写出要看的节点。配置了 `S3DFS_ALERT_URL` 才把 `lost` 和布局不 ok 送出去。升级顺序写在部署文档里，不自动跳版本 | 规则自动。盘故障和校验错误可以发到本机事件。大版本升级仍是人做 |

## 文件系统放在一起

成熟度只使用这五档：没有、手工、规则自动、闭环、产品。闭环指发现之后会处理，并再看结果。产品指边界和运行记录已经交给值班使用，不依赖读源码。下面只比本目录里的单机文件系统。s3dfs 这一行在各篇里相同。NFS、SMB、Ceph、Longhorn、GFS、TFS、FastDFS 和 RustFS 不在这张表里，各自的档仍写在该篇里。

| 系统 | 自我修复 | 静默损坏巡检 | 自运维 | 告警与升级 | 停在哪 |
| --- | --- | --- | --- | --- | --- |
| s3dfs | 规则自动 | 规则自动 | 规则自动 | 手工 | 副本不够会再写一份，Get 时 CRC 不对就换一份。scrub 按 locator 留下计数，但没有把没有索引的 `.blk` 再读一遍。告警要配置地址才送出 |
| ZFS | 闭环 | 闭环 | 规则自动 | 规则自动 | 读到坏块当场修，scrub 把没人读的块也走一遍，结果留在池的错误计数里。池在一台机器上 |
| Btrfs | 规则自动 | 规则自动 | 手工 | 手工 | RAID 1/10 的 scrub 可以用另一份修。scrub 和 balance 要人安排。RAID 5/6 不能当唯一副本 |
| HAMMER2 | 规则自动 | 规则自动 | 手工 | 手工 | 读时用 CRC，从卷可以恢复这一卷。没有默认定时把整卷读完并修好 |
| APFS | 手工 | 规则自动 | 手工 | 手工 | 元数据核对 Fletcher-64。用户数据没有第二份，静默损坏靠盘 |
| NTFS | 规则自动 | 没有 | 手工 | 手工 | 在线修复和日志重放管元数据。用户数据没有端到端校验，也没有第二份副本 |
| FFS | 手工 | 没有 | 手工 | 手工 | fsck 由人发起。数据块没有端到端校验。GEOM 镜像不自动跨机器补一份 |

s3dfs 和 ZFS 的差距在闭环：ZFS 的 scrub 覆盖没人读过的块。s3dfs 的 `scrub` 按 locator 修并留下计数，不扫没有索引的字节。s3dfs 与 Btrfs、HAMMER2 同在规则自动，还没有到 ZFS 那一档。APFS 的用户数据没有可以换上的第二份。NTFS 和 FFS 的用户数据没有端到端校验。这些文件系统都不提供跨 zone 的 S3。

s3dfs 现在停在规则自动。下面两档还没有。纠删、KMS 和整集群的站点同步不在这张差距表里。身份账本、对象锁和桶复制开关已经有第一版。

| 还差的档 | 还缺什么 |
| --- | --- |
| 闭环 | 把没有索引的 `.blk` 再读一遍。按 locator 的巡检已经会修并留下计数。停一台 block 或一台索引之后，健康检查回到 200 要多久，还没有在目标集群测过 |
| 产品 | 准备接流量的集群上还没有容量数字，也没有五步演练的部署笔记。告警只在配置了地址时送出，升级顺序已经写给值班，目标集群还没按这个顺序走过。本机 localhost 的通过不能当作唯一副本 |

## 省心与数据保护

这一节写值班的人和数据本身。修复与运维一节是修复做到哪一档。这里写人可以不碰什么、人仍然必须碰什么，以及写下去、读出来、删错、整机丢失和另一场地各保护到哪。

| 项 | s3dfs | ZFS |
| --- | --- | --- |
| 值班可以不碰 | 一台 block 宕了，不用改客户端，也不用手工指定另一台。读会换活副本，新的 Put 不再选这台。周期 repair 把第 3 份补上，并去掉指向 down 节点的 locator。flush 和 compact 到了阈值自己跑。巡检先给四段简报，人看「值班下一步」，不必先从七个模块的原始数字里找 | 盘返回了对不上父指针的数据，池里还有冗余就会在这次读里修好，不用先跑一遍整盘检查。scrub 可以放进计划任务。做快照不用先把池拷一份 |
| 值班仍要碰 | 换盘，并把盘装回原来的 nodeId。确认 `lost` 里的对象是不是业务唯一的一份。在真正承接流量的集群上做演练。没配扩容命令时，加机器是人做的。旧对象不会自己搬到新 block。索引达不到法定人数，或三份正文都没了，没有按钮能把字节变出来 | 换哪块盘要人下命令，或事先把自动替换的盘位配好。池在这台机器上，主板没了，镜像和 RAID-Z 一起没。送到哪一台、快照留几份、配额谁告警，都要人定 |
| 写下去 | 默认 3 个 zone 里至少 2 台 block 落盘，才把 locator 写入索引。第 3 份可以稍后补。这次的 locator 没有写齐，已经写下的会删掉，调用方看不到半份。索引还要达到 dleveldb 的法定人数 | 事务把新块写完再改指针。崩溃后读者看不到半块。这不拦住 `rm` 和 `zfs destroy` |
| 读出来 | Get 按 locator 找还活着的节点，核对大小和 CRC，不对就换下一份。Head 在节点暂时不可达时可以用索引里的 size、crc、mtime，那是没有把正文读出来核对 | 校验和在父指针里，盘自己编一段看起来完整的错数据也对不上。scrub 把没有人读的块也查一遍，能修的当时修 |
| 删错和覆盖 | Delete 后索引里立刻看不见。盘上先留墓碑，compact 才收回空间。墓碑防止扫 `.blk` 时把已删对象救回来。覆盖是新的 locator。开了版本时，旧正文在同一组 block 的 `$ver/` 里，不是另一场地的备份 | 还被快照引用的块删不掉。没有快照的删除就是删除。毁掉一个数据集或池没有回收站 |
| 整机或整盘没了 | 丢一台、对象还有活副本时，读可以继续；还有空闲节点就再补一份。三份都在丢了的盘上，或当时只写成一份且那份没了，记为 `lost`，健康检查失败，字节补不回来。`lost` 写在 `$lost/`，重启后还在 | 一块盘没了，resilver 补到替换盘上。整台机器没了，只剩下已经 `zfs send` 出去的那一份 |
| 另一场地 | 默认不把对象送到另一套集群。桶上打开复制并配置了地址之后，之后的 Put 和 Delete 才送出。3 副本仍是这一套集群里的三台 block | `zfs send` / `recv` 是明确的第二份池。不配发送目标和保留，就没有另一场地 |

## 特色

| 只在 ZFS 里的做法 | 它怎么做 | s3dfs 现在 |
| --- | --- | --- |
| 校验和在父指针里 | 块自己身上没有「我是对的」这种自述。盘若返回一段自洽但错误的数据，父指针对不上 | 记录上的 CRC 和 locator 里的正文 CRC 是分开的两处。记录若整段被换成另一段合法记录，要靠 key 和 locator 对上 |
| scrub 和 resilver 分开 | scrub 是全池巡检，不要求先缺盘。resilver 是缺了冗余之后补到新盘 | `repair` 补缺少的份数。`scrub` 按 locator 重写坏副本并留下计数，不扫没有索引的字节 |
| RAID-Z | 条带加 1 到 3 份校验，用容量换冗余。仍然在一个池里 | 默认是 3 份整对象。不用纠删替换 `.blk` |
| 数据集 | 压缩、配额、预留、快照都挂在数据集上，比「整个池一个开关」更细 | 压缩默认开，桶上可以关掉并设 `quotaBytes`。版本是 `$ver/` 里的对象，不是数据集快照 |
| send / recv | 把两个快照之间的块差复制到另一台池，不必把每个文件再读一遍 | 没有整池增量。桶上打开复制之后，之后的 Put 和 Delete 才送到另一套，默认不送 |

## 留下的

校验和和正文分开存，静默损坏盖不过父指针。全量巡检和「副本份数不够就再写一份」分开做。快照加上 send/recv 是整池备份的形状：记某一刻还活着的块，而不是把每个 key 再 Put 一遍。压缩和配额按数据集开，比全局一个开关更细。

## 不照搬的部分

不用 RAID-Z 替换 `.blk` 的 3 副本。池在一台机器上，扛不住按 zone 丢掉整台机器。不把快照做成在线的 S3 版本；版本正文已经在 block 的 `$ver/`。
