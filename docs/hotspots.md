热点在一次写入被确认之前必须做完的那一段。块线程加到 32 之后，小对象和 1 MiB 的天花板都没有抬高。

## 确认路径

默认 3 份副本，写法定人数是当次选出副本数的多数。要等够这个份数的正文，并把已经成功的数据位置写入索引，才返回。其余副本在返回之后继续写。

`S3DFS_WRITE_QUORUM=1` 时只等一份。这一份是这台 API 自己的磁盘。本机盘不能写时，再等下一台活着的盘。正文写完后，把节点和 `recId` 写入索引，然后返回。另外两份副本仍在返回之后写，并补上它们的数据位置。

被等的那一份在块线程里做两次写：

1. 正文 `pwrite` 到这个线程自己的 `.blk`。
2. 定位写这一格的 4 字节偏移。

不再把这一页 80 KiB 槽重算成 CRC，页头里那 4 字节写入时填 0，打开时也不核对。槽必须指向已经写出的正文，所以对象不能先攒在内存里一起刷。fsync 大约每 30 秒一次，不在每次请求上。

接入线程和块线程是分开的。接入线程（`S3DFS_BLOCK_WRITE_THREADS`，默认 32）接住本机写入和对端 :9100。块线程（`S3DFS_WRITE_BLOCKS`，默认 8，最多 32）才追加文件，一条线程只打开一个 `.blk`。同一个 key 总是进同一条线程。同时在写的文件数等于块线程数。

## 2026-11-22 晚上

三台测试机，压缩关掉，对象副本 3，写法定人数 1。两台 API 的磁盘在 API 进程里，没有 API 的那台单独跑磁盘。盘上已经有更早的对象。客户端在这三台上跑，不从另一台机器发起。没有 API 的那台打到 16 核那台的 API，所以 16 核同时接了两路。不要和本机 localhost 的数字相减，也不要把下面两张表的 ops/s 相减。

同一天更早，一台客户端串行写 1 KiB，p50 大约 7 毫秒。本机引擎单独写 1 KiB，p50 大约 0.9 毫秒。多出来的是这一跳副本和那条数据位置。

一块盘 8 个 `.blk`、每路 30 并发，和后来 32 个 `.blk`、每路 32 并发，小对象没有变快，1 MiB 仍在每路大约 100 ops/s。当时要等的那一份副本按 key 哈希选出，经常不在发起请求的 API 上。

| 写入 | 16 核，本机 API | 8 核，本机 API | 8 核，打到 16 核的 API |
| --- | ---: | ---: | ---: |
| 1 KiB ×32 | 266.6 ops/s | 360.5 ops/s | 267.9 ops/s |
| 10 KiB ×32 | 155.7 ops/s | 515.2 ops/s | 154.8 ops/s |
| 100 KiB ×32 | 412.2 ops/s | 471.1 ops/s | 365.0 ops/s |
| 1 MiB ×32 | 102.3 ops/s | 110.2 ops/s | 104.0 ops/s |

改成先等本机磁盘和本机数据位置之后，同样是 32 个 `.blk`、每路 32 并发：

| 写入 | 16 核，本机 API | 8 核，本机 API | 8 核，打到 16 核的 API |
| --- | ---: | ---: | ---: |
| 1 KiB ×32 | 258.5 ops/s | 365.5 ops/s | 257.7 ops/s |
| 10 KiB ×32 | 296.8 ops/s | 378.8 ops/s | 298.0 ops/s |
| 100 KiB ×32 | 193.3 ops/s | 422.3 ops/s | 192.4 ops/s |
| 1 MiB ×32 | 50.7 ops/s | 106.6 ops/s | 54.3 ops/s |

8 核只有自己这一路，大约 22:15:45 结束。另外两路大约 22:15:47 结束。30 并发和 32 并发的行不是同一小段时间，不能把三列加起来当成集群总吞吐。100 KiB 只有 80 次。请求都返回成功。

两路挤在 16 核上的 10 KiB 从 155.7 和 154.8 ops/s 升到 296.8 和 298.0。1 MiB 从大约 100 ops/s 掉到 50.7 和 54.3。这两路的确认都压在 16 核自己的磁盘上，整兆正文要在这台盘写完才返回。8 核自己这一路的 1 MiB 仍是 106.6 ops/s。

## 现在卡在哪

每次确认都要等一份副本做完上面两次写，再写一条数据位置。下面的数字是在还重算 80 KiB 槽 CRC 时测的。返回之后的另外两份副本继续占用这三块盘。多开 `.blk` 已经不抬高这段的吞吐。产品默认仍是 8 个文件。32 个文件只用于上面这次测量。
