# 按负载自动扩缩容

日期：2026-11-20。

| | |
| --- | --- |
| 读者 | 实现和验收这套自运维的人 |
| 决定 | API 内的评估器做决策。启停交给外部脚本。缩容前先排空 |
| 范围 | 索引、block、API 三层。阈值可配置。不创建云主机，不在进程内拉起子进程 |

## 1. 控制回路

评估器跑在 API 进程里，默认 30 秒一次。`S3DFS_SCALE_INTERVAL_MS=0` 关闭。

多台 API 同时运行时，只有拿到索引租约的那一台评估。租约是索引里的一条带过期时间的记录。没拿到租约的 API 不调用脚本。

一次评估只处理一个角色的一个动作，顺序固定为索引、block、API。避免三层在同一个周期里一起增减。

### 信号

| 角色 | 容量 | 延迟 |
| --- | --- | --- |
| block | 已用字节 / 配置的容量 | 本周期写入延迟 |
| 索引 | key 数量，以及本机分片体积 | 本周期索引写入延迟 |
| API | 在途请求数 | 本周期请求延迟 |

阈值全部来自环境变量，不把某一次本机测量写进代码。容量用占用比例，延迟用本周期 p99。

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `S3DFS_SCALE_HIGH_RATIO` | `0.80` | 容量高于此比例，计为容量偏高 |
| `S3DFS_SCALE_LOW_RATIO` | `0.40` | 容量低于此比例，才允许缩容 |
| `S3DFS_SCALE_HIGH_LATENCY_MS` | `200` | 延迟 p99 高于此值，计为延迟偏高 |
| `S3DFS_SCALE_LOW_LATENCY_MS` | `50` | 延迟 p99 低于此值，才允许缩容 |
| `S3DFS_SCALE_HIGH_STREAK` | `3` | 连续多少个周期超阈值才扩容 |
| `S3DFS_SCALE_COOLDOWN_MS` | `300000` | 一次动作之后，多久内不再对同一角色动作 |
| `S3DFS_BLOCK_CAPACITY_BYTES` | 必填才会按磁盘扩缩 | block 容量。未设置时，block 只按延迟扩缩 |
| `S3DFS_INDEX_CAPACITY_BYTES` | 必填才会按体积扩缩 | 索引分片容量。未设置时，索引只按 key 数量上限和延迟扩缩 |
| `S3DFS_INDEX_MAX_KEYS` | `100000000` | 单节点 key 数量上限 |
| `S3DFS_API_MAX_INFLIGHT` | `128` | API 在途请求上限 |

扩容：该角色的容量或延迟连续超过自己的高阈值，达到 `S3DFS_SCALE_HIGH_STREAK`。

缩容：该角色的容量和延迟都低于自己的低阈值，并且距该角色上一次动作已超过 `S3DFS_SCALE_COOLDOWN_MS`。

## 2. 扩容

评估器执行 `S3DFS_SCALE_UP_CMD`。环境变量：

| 变量 | 含义 |
| --- | --- |
| `S3DFS_SCALE_ROLE` | `block`、`index` 或 `api` |
| `S3DFS_SCALE_REASON` | `capacity` 或 `latency` |

脚本负责开机，并让新进程按现有方式加入：

- block 注册进索引，并带上 `@zone`
- 索引用 `DLEVELDB_PEERS` 加入环，由 dleveldb 按较新的 mtime 追平
- API 挂到已有负载均衡后面

脚本非 0 退出只记日志。下个周期可以再试。失败不算已经扩容，不推进冷却窗口。

## 3. 缩容

先把目标标成 `draining`。新写入不再选择它。

| 角色 | 允许调用停机脚本的条件 |
| --- | --- |
| block | 修复已把对象补到其他存活节点，没有任何活数据位置再指向它 |
| 索引 | 评估器向其余存活节点读取该节点负责的 key，读到的值与该节点本地值一致，且剩下的节点仍达到写法定人数。不一致就继续等 dleveldb 的追平 |
| API | 本进程在途请求已结束 |

任一条件不满足，保持 `draining`，不执行停机脚本。

条件都满足后执行 `S3DFS_SCALE_DOWN_CMD`，环境变量为 `S3DFS_SCALE_ROLE`、`S3DFS_SCALE_NODE_ID`、`S3DFS_SCALE_ADDRESS`。

硬边界：

- block 不能缩到少于 `S3DFS_DATA_REPLICAS`，也不能缩到故障域少于严格布局的要求
- 索引不能缩到少于 3 个节点
- 只剩一台 API 时不缩 API

脚本失败时节点保持 `draining`，下个周期再试停机，不把节点放回可写集合。

## 4. 失败

| 情况 | 行为 |
| --- | --- |
| 脚本不存在或未配置 | 评估器不动作，健康检查仍按现有规则 |
| 脚本超时或非 0 退出 | 记日志，下个周期重试 |
| 排空迁不走 | 保持 `draining`，不调用停机脚本 |
| 租约丢失 | 本进程停止评估，不留下半次启停 |

## 5. 测试

决策函数不启动进程、不调用脚本。

| 用例 | 期望 |
| --- | --- |
| 容量或延迟连续超阈值 | 选出对应角色的扩容 |
| 两项都低，但冷却未满 | 不动作 |
| 两项都低，且冷却已满 | 选出缩容 |
| block 仍有活数据位置 | 不允许停机 |
| 缩容后故障域或副本数不够 | 不允许停机 |
| 索引剩下的节点达不到法定人数 | 不允许停机 |
| 同一周期三个角色都超阈值 | 只处理索引 |

脚本执行器用注入的函数测试：成功才进入冷却，失败则下个周期仍可再试。
