架构

一台机器一个进程。对外只有 S3 API。索引、入盘和给其他节点用的数据端口都在这个进程里，分成多条线程。S3 解析在 TypeScript。正文追加在 C 引擎。

S3 客户端

AWS CLI、SDK、控制台和 FUSE 关闭文件时的整文件上传。协议是 S3。ETag 是 CRC32。

API 进程 apps/api :9000

唯一对外的接口。鉴权、桶、列举、分片、选块和数据位置都在 TypeScript 里。

  1. 按对象 key 从存活节点里选副本，默认 3 份，优先不同故障域。
  2. 本机那一份直接调用本进程里的 C 引擎，不再绕一圈 HTTP。
  3. 其余副本 HTTP 到对端同一进程的 :9100。对端用 C 线程把字节追加进自己的 .blk。
  4. 默认写满当次副本数的多数，再把数据位置写入索引。记录是节点和 recId。S3DFS_WRITE_QUORUM=1 时只等本机磁盘上的那一份和它的数据位置。
  5. 向客户端返回。还没写完的副本由这台 API 随后补上。

本进程里的引擎

S3DFS_DATA_DIR 由 API 打开。默认 8 条写入线程，每条打开自己的一个 .blk，最多 32 个。每个对象先写出正文，再定位写 4 字节槽。打开时读页，不扫对象正文，也不核对页上的槽 CRC。大约每 30 秒 fsync。

本进程里的索引

设置 DLEVELDB_DATA_DIR 时，dleveldb 跑在这个进程里，并仍对其他节点提供 :9800。没有这份目录时，API 用 HTTP 访问单独的索引进程。索引只存数据位置，不存对象正文。

不承接对象正文的部分

控制台 :9001

apps/web。看状态、触发 flush。

巡检和 FUSE

  • 巡检 apps/patrol。按规则做维护，写中文结论。不决定删除、重启或缩容。
  • FUSE 把桶挂成目录。关闭文件时整文件交给这台 API。
